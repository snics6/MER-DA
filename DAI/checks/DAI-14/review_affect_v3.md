## 重大な指摘

### [A1] MOSEI の #shuffine は Neutral の中だけを分け，Happy・Sad・Angry の中の感情の強さを分けない
- 箇所：設計 3 節 42 行「MOSEI は（感情の強さ int_* の最大の 3 区分）で分けた層の中で入れ替える．3 区分の境は単位の候補の上の 3 分位（同じ値が多いので 3 等分にはならない…）．#shufcl と入れ子なので，D_shuffine は『D から，さらに覚醒度か強さを通した一致を除いた分』と読める」．設計 5 節 70 行「#shufcl と #shuffine で違う予言は『覚醒度か強さを通した一致で説明できる分を含む』と書き」．台本 235〜239 行 `fine_strata`（`q = np.nanquantile(v, [1 / 3, 2 / 3])` を 4 感情をまとめた候補の全体で計算する）．
- 問題：MOSEI の 4 感情のラベルは強さから決まる．Neutral はどの強さも 0.5 未満の発話なので最大の強さは 0 か 1/3 に限られ，Happy・Sad・Angry は最大の強さが 2/3 以上になる．4 感情をまとめた候補の 3 分位の境は 1/3 と 2/3 になる．この検査で `DAI/splits/MOSEI.csv` の分割 0 以外の発話（14,907 本．評価の回の候補に近い集まり）を台本と同じ規則で区分すると，次のようになった．

  | 感情 | 区分 0 | 区分 1 | 区分 2 |
  |---|---|---|---|
  | Neutral | 2,596 | 4,282 | 0 |
  | Happy | 0 | 7 | 5,371 |
  | Sad | 0 | 3 | 1,504 |
  | Angry | 0 | 0 | 1,144 |

  Happy・Sad・Angry はほぼ全部が区分 2 に入るので，この 3 感情では #shuffine の層は #shufcl の層と同じである．Happy の中の強さは 2/3（1,675 本），1（1,236 本），4/3（937 本），5/3（689 本），2（476 本）と散らばっており，言葉の分類器の判断が「強い Happy」と「弱い Happy」で違う可能性は除かれない．このため MOSEI で D と D_shuffine が同じ判定になっても，「強さを通した一致では説明できない」とは書けない．IEMOCAP は覚醒度の境（2.5 と 3.5）で 4 感情のどれも 2〜3 区分に分かれるので，この問題は無い（Neutral 139／554／119，Happy 7／228／432，Sad 210／238／27，Angry 2／59／197）．
- DAI の基準との関係：報告の誤りに当たる．設計の読み（「強さを通した一致を除いた分」）は，MOSEI では Neutral の中の強さ（0 と 1/3）を除いた分にしか当たらない．
- 直し方（どちらか 1 つ）：
  1. 台本の `fine_strata` で，3 分位の境を本当の感情ごとに候補の上で決める（ラベルは入れ替えの層を作るためにすでに使っており，新しい情報は増えない）．上と同じ集まりで数えると，感情ごとの境は Happy で 1 と 4/3（1,686／1,239／2,453 本），Sad と Angry で 2/3 と 1（実質 2 区分），Neutral で 0 と 1/3（2 区分）になる．層が小さくなり，1 本だけの層に入る発話は約 9%（#shufcl）から約 20% に，3 本以下の層は約 30% から約 54% に増える（推測．チャンネルの層をこの集まりで数えた値）．入れ替えで目標が変わる割合が下がって D_shuffine が 0 に寄る向きなので，8 節の基準（frac_changed の平均 0.40 未満）を #shuffine にも当てる．IEMOCAP にも同じ規則を当てるかは設計で決めて書く（今の IEMOCAP の区分は感情の中でも分かれているので，どちらでもよい）．台本を直したら gate-code に差分を検査させる．
  2. 台本は直さず，設計 3 節・5 節・9 節に「MOSEI の #shuffine は Neutral の中の強さ（0 と 1/3）だけを分け，Happy・Sad・Angry の中の強さは分けない」と書き，結果の文で MOSEI の #shuffine を「Neutral の中の弱い感情の混ざりを除いた版」とだけ読む．MOSEI で D と D_shuffine の判定が同じでも「強さでは説明できない」と書かない．

## 軽微な指摘

- [a1] 第 2 版の A1 の直し方 2 のうち，AFEW の部分が 9 節に無い．AFEW の #shufcl の層は（感情，俳優と作品をつないだ塊，性別）で，1 つの塊に同じ性別の俳優が複数いる．俳優ごとの判断の偏り（顔の分類器が特定の俳優に Angry を多く付けるなど）は入れ替えで壊れて D に残り，声の特徴は話者を強く表すので声の生徒に有利な向きである．AFEW は P2・P4b の主の数え（4 コーパスで 3 以上）に入る．俳優ごとの層は件数が足りない（第 2 版の報告で数えた俳優 × 感情の中央値 1 発話）ので層は今のままでよく，9 節に「AFEW の D には，同じ塊の同じ性別の俳優の間の偏りが残る（P2・P4b で声に有利な向き）」と書く．5 節の書き方の表の「話者の単位」も，結果の文でコーパスごとの中身（IEMOCAP は話者，MELD は話者，AFEW は俳優と作品の塊と性別，MOSEI はチャンネルか動画）を書く．
- [a2] 主張の文書 `DAI/docs/主張_2026-11-12.md` 3 節は，検証できる 2 点目を「感情のラベルと塊（話者の代わり）で説明できない部分」と書いたままである．設計の第 3 版の語（「感情のラベルと話者の単位」）に合わせ，IEMOCAP と AFEW では性別も層に入ることを書く．
- [a3] 第 2 版の a7（MOSEI の細かい層は 6 つの強さの最大で作るので，Happy の発話でも最大が別の感情の強さになりうる）は，設計に「int_* の最大」とあるだけで，読み方の注意が無い．A1 を直し方 1 で直す場合も残るので，結果の文に「感情の強さの最大であって，その感情の強さではない」と書く．
- [a4] 第 2 版の a3（K = 25 では K 本の 100 発話が候補に入り，AFEW では候補の 1 割を超える）は設計に入っていない．分割 0 以外の AFEW の発話は 632 本なので，K 本は約 16% になる（推測．評価の回の候補はこれより少し少ない）．K 本の上では J_m は学んだラベルにほぼ一致し，#shufcl の入れ替えでも目標が変わりにくい．K = 25 は副の条件で，台本は K 本の印 `nk__K25` を保存するので，計算をやり直さずに K 本を除いた R を出せる．査読で問われたら出せばよく，計算の前に直す必要は無い．
- [a5] MOSEI の丸括弧には，言いよどみの印（(umm)，(uhh)，(stutter)）のほかに編集の補足（「(Ukraine)」「(GLD)」など）も入る．記号の無い版はどちらも除くので判定の作りには問題が無いが，「記号は声の手がかり」と書くときは，MOSEI の丸括弧の一部は声の手がかりではないと書く．設計 86 行の割合（IEMOCAP 4.6%，MELD 26.9%，AFEW 14.7%，MOSEI 14.6%）は，この検査で `DAI/splits/<T>.csv` の発話に台本の正規表現を当てて数えた値と一致した．

## 確かめたこと

- 役の定義，`DAI/CLAUDE.md`，設計の全文（12 節を含む），台本の層と部分集合と入れ替えの部分（195〜260 行，420〜500 行，565〜760 行の該当箇所，selftest の 815〜860 行），主張の文書，台帳の DAI-14 の行，前の版のこの役の報告 2 本と第 2 版の関門の報告の判定の部分を読んだ．
- 第 2 版 A1（IEMOCAP の話者）：台本 435〜436 行の #shufcl の層は（感情，塊，性別）で，IEMOCAP の性別は発話一覧の `utterance_speaker` である．`utterance_speaker` は 2,943 発話すべてで `sample_id` の最後の部分の頭の文字（Ses01F_impro01_**M**003 の M）と一致し，塊はセッション（Ses01 など）なので，層は（感情，話者）になる．分割 0 以外の発話で数えると，この層は 32 個で，1 本だけの層は無い．性別の欠けは IEMOCAP・AFEW とも 0 で，欠けがあれば台本が止まる（230〜231 行）．層は塊の中に入れ子なので，入れ替えは 2 つの組をまたがない．設計 2 節の塊の説明は台本どおりに直った．selftest に，塊をまたいで共通な属性で判断が偏る合成の対照（感情だけの入れ替えでは D > 0，（感情，塊，属性）では D ≈ 0）が入った．
- 第 2 版 A2（#shuffine の入れ子）：台本 437 行で #shuffine の層は #shufcl の層に細かい区分をつないだものになり，入れ子である．3 区分の境は単位の候補の上で決まり（`corpus_meta(T).reindex(sv.sid_pool)`），テストの発話を使わない．P3・P4a・P4b は対照 `fine` でも作られ（698 行），#shuffine は 2 コーパスだけなので数えずにコーパスごとに並べる（756 行，設計 70 行）．IEMOCAP では区分が感情の中でも分かれる．MOSEI の問題は上の A1．
- 第 2 版 a1：9 節に即興の 8 つの筋書きの共有と，顔のモーションキャプチャのマーカー（候補の約 51%）が入った．
- 第 2 版 a2：記号の正規表現は角・丸・波括弧と「!」になり（台本 49 行），「?」を含めない理由が設計 86 行にある．割合は上の a5 のとおり一致した．
- 第 2 版 a4：Albanie ほか 2018 が 9 節に入り，設定の違い（生徒の音声の識別器を学習するか，凍結した特徴の上の線形の識別器か）も書かれた．
- 第 2 版 a5：9 節に AFEW の Whisper の定型の文（繰り返しの疑いの 33 本）と，2 つの組に同じ書き起こしがある発話（1.7〜2.5%）が入った．
- 第 2 版 a6：8 節の基準は「0.40 未満」に固定され，そのとき D が 0 に寄る向きと書き方が書かれた．
- 第 1 版の指摘（書き起こしの記号，覚醒度・強さの限界，AFEW の声と言葉が同じ信号であること，MELD の共有の対話）は第 2 版で直ったまま残っている．J_T を使う予言（P1・P3・P4a）は AFEW を除く 3 コーパスで数える．
- 評価のターゲットのテストの発話は使われない．本当のラベルと注釈は，入れ替えの層，当たる幅，真似できる分にだけ使われ，R1 の C′ は目標の判断との一致で選ばれる．
- ラベルの対応とコーパスの扱い（IEMOCAP は即興だけ，excited を Happy に入れ frustration を入れない，MELD の複数の人の声と合同発話を落とす，3 モダリティがそろう発話だけ）は評価の回と同じである．
- データの申告：新しいデータを使わず，保存済みの出力を解析し直すだけなので，評価の回の利用条件と倫理の申告がそのまま当てはまる．
