## 重大な指摘

### [M1] IEMOCAP と AFEW では #shufcl が話者の性別を通した一致を除かず，P4b が声に有利な向きに偏る
- 箇所：設計 3 節「#shufcl（P3・P4 の主）：（本当の感情，塊）が同じ候補の間で入れ替える．……話者や対話に固有の偏りによる一致はこの対照に残るので，D から除かれる」．5 節の書き方の表「感情のラベルと塊（話者の代わり）で説明できない部分」．台本 `run_unit` の `st_cl = y | cl`．塊の定義 `DAI/exp/dai_data.py` の `clusters`：IEMOCAP は `sample_id[:5]`（セッション），AFEW は俳優と作品のつながりでまとめた塊，MELD は話者，MOSEI は `speaker_group`．
- 問題：
  - IEMOCAP の 1 つのセッションには男女 1 人ずつの 2 人の話者がいる．AFEW の塊は同じ作品に出る俳優をまとめるので，男女が混ざる．この 2 コーパスでは，#shufcl は 1 つの塊の中で男性の発話と女性の発話の間でも判断を入れ替える．
  - 例：顔の分類器の判断 J_V が，同じ「Neutral」の発話でも女性の顔に「Happy」を多く付けるとする．声の特徴は性別をほぼ完全に持つので，声の識別器は片方の組で「女性なら Happy」を学び，もう片方の組の女性の話者にも当てて一致を上げる．#shufcl はセッションの中で男女をまたいで入れ替えるので，入れ替えた目標からはこの偏りが消える．このため R(A ← V) − R_shufcl(A ← V) には性別を通した一致が残る．言葉の特徴（書き起こしの RoBERTa）は性別をあまり持たないので，D(T ← V) には同じ分がほとんど残らない．結果として P4b = D(A ← V) − D(T ← V) は，「声に表情の手がかりが入っている」が偽でも，性別だけで正になる向きに偏る．
  - P4b の主の数えは「4 コーパスで 3 以上」なので，IEMOCAP と AFEW の 2 票がこの偏りで入りうる．P3 と P4a の IEMOCAP の票にも同じ分が入りうる（P4a は声と顔がともに性別を持つので一部は打ち消し合う）．
  - 5 節の文「塊（話者の代わり）」は，IEMOCAP と AFEW では測っている量と合わない．塊は話者ではない．
  - 第 1 版の関門の compare（C1）は「本当の感情 × 話者」の入れ替えを求め，第 1 版の私の報告の M2 は塊が話者に当たると考えて「感情 × 塊」を勧めた．後者は IEMOCAP と AFEW の塊の作りを確かめていなかった．11 節の変更の表は compare の C1 を対応の出所に挙げていない．
  - 9 節は「話者の属性（性別など．塊の中で一定でない分）」を限界に書く．しかし，ここで問題になるのは誤差が増えることではなく，判定する量そのものが仮説の向きに偏ることである．限界の 1 文では足りない．
- DAI の基準との関係：報告の誤りに当たる（P4b の当たりを「声の特徴は，顔の分類器の判断のうち感情と話者で説明できない部分を言葉の特徴より多く再現した」と書くと，IEMOCAP と AFEW では事実と違う）．
- 直し方（どれも計算の前に設計 3・5 節と台本を直す．計算はほとんど増えない）：
  1. 主の対照の層を，性別が塊の中で変わるコーパスで細かくする．IEMOCAP は（本当の感情，話者）にする．話者は発話一覧の `utterance_speaker`（または `sample_id` のセッションと末尾の F／M）で決まり，セッション × 性別の 10 人と一致する．AFEW は（本当の感情，塊，性別）にする（発話一覧の `gender` の列）．MELD と MOSEI は塊が話者の単位なので今のままでよい．層が細かくなるので，`frac_changed`（目標が変わった発話の割合）を今と同じく出す．
  2. 1 を主にせず副の対照（例：#shufsp）として足すなら，「#shufcl で上回り，#shufsp で上回らないコーパスは主の数えで上回るに数えない」を 5 節に足す（MELD の共有の対話の規則と同じ形）．
  3. 5 節の書き方の表の「塊（話者の代わり）」を，選んだ層の名前に合わせて直す（例：「感情のラベルと話者（MOSEI はチャンネルか動画）」）．
  4. selftest に，特徴が感情と性別だけを持ち，判断が性別で偏るときに，新しい層の D がほぼ 0 になる場合を 1 つ足す．

### [M2] 分け方の揺れの項は，5 つの分割で分け方の誤差が独立だと仮定しているが，誤差は分割の間でそろいうる
- 箇所：設計 4 節「分割 f ごとの分け方の間の分散 v_f を求め，(1/F²) Σ_f v_f を主の区間の SE² に足す」．台本 `combo_stats` の `v_split = sum(vs) / F ** 2`．
- 問題：
  - 推定値は 5 つの分割の値の平均で，各分割は元の分け方（`dai3.pool_halves`．塊を大きい順に本数の少ない組へ配る決まった規則）1 つだけを使う．分け方による誤差を e_f と書くと，平均の誤差の分散は (1/F²) Σ_f Σ_g Cov(e_f, e_g) である．(1/F²) Σ_f v_f は共分散の項を 0 とおいた値で，e_f が分割の間で独立なときだけ正しい．
  - 分割どうしは候補の約 3/4 を共有し（関門の stats の第 1 版），元の分け方は同じ規則で作るので，同じ塊の組が別の分割で繰り返し現れる．stats の第 1 版は IEMOCAP の分割 0 と 1 で同じ組が現れることを確かめた．IEMOCAP では候補が 4 セッションで，2 対 2 の分け方は 3 通りしかないので，そろいやすい．
  - 誤差が分割の間で完全にそろうと，分け方の項の分散は (1/F) × v の平均になり，今の式の 5 倍になる（標準誤差では約 2.2 倍）．今の式は区間を狭く出す向きに偏り，偽の「上回る」が増える．
- DAI の基準との関係：報告の誤り（区間の幅を実際より狭く報告する）に当たる．
- 直し方：
  1. 共分散の上限で足す．Var(平均の誤差) ≤ (Σ_f √v_f / F)² ≤ (1/F) Σ_f v_f なので，(1/F) Σ_f v_f（分割の間で完全にそろうとした保守的な値）を主の SE² に足す．台本では `/ F ** 2` を `/ F` に変える 1 行で済む．
  2. 独立の式を残したい場合は，両方の区間を `predictions.csv` に列で残し，「保守的な式で下端 > 0」を主の判定にすると 5 節に書く．
  3. いずれも 4 節に，元の分け方が分割の間で共有する塊の組を数えて記録すると書く（npz の `half` と `althalf__*` から後で数えられる）．

## 軽微な指摘

- [m1] R1 の C′ を真の目標で選び，入れ替えた目標にもそのまま当てるので，帰無（特徴が感情と塊しか持たない）でも D が少し正に寄りうる．選んだ C′ は真の目標の学習側の組に合わせてあり，入れ替えた目標には合わせていないからである．手順を対称にする（入れ替えた目標にも同じ内側の交差の予測で C′ を選ぶ）と，帰無で入れ替えた目標と真の目標は同じ分布になるので，E[D] = 0 が作りの上で成り立つ．私が台本の `fit_r1` で合成の数を作って試した（n = 1,200，d = 200，特徴は感情だけ，判断は半分を乱数で置き換え，#shufcl で入れ替え，40 回）ところ，台本どおりの D の平均は 0.10（標準誤差 0.37），対称にした D の平均は −0.07（同 0.45）で，差は検出できなかった（台本 `/tmp/claude-1000/-home-snics-MER-DA/76085a37-4610-4922-b8ae-ced34f163c39/scratchpad/sim_cbias.py`）．合成の数で偏りが小さかったので重大な指摘にはしないが，実データで同じとは限らない．次のどちらかにする．(a) 入れ替えた目標にも C′ を同じ手順で選ぶ（内側の問が 3〜4 倍になる）．(b) 台本どおりにし，8 節の仮定の表に「対照に真の目標の C′ を当てる．帰無で D が正に寄る分は合成の数で 0.1 前後」と書く．
- [m2] #shuffine の層は（本当の感情，細かい層）で，塊を含まない（台本の `st_f = y | fine`）．このため R_shuffine は #shufcl が除く塊の水準の一致を再び含み，D_shuffine と D_shufcl の差は「覚醒度・強さの分」と読めない．層を（本当の感情，塊（M1 で直した層），細かい層）にすると，#shufcl より厳しく細かい対照になり，D_shufcl − D_shuffine を覚醒度・強さを通した分として並べられる．あわせて，IEMOCAP・MOSEI で P4a・P4b が #shufcl で当たり #shuffine で当たらないときの文（例：「覚醒度・強さの 3 区分の中で入れ替えると差は判定できなかった」）を 5 節に固定する．覚醒度は声が強く表す性質なので，P4a の最も有力な代わりの説明である．
- [m3] 8 節の「割合が小さい（約 40% 未満）コーパスでは D の解釈を弱める」は，境が「約」で，弱める向きも決まっていない．入れ替えで変わる発話が少ないと，入れ替えた目標は真の目標に近くなり，D は 0 に寄る．つまり割合が小さいと当たりにくくなる（保守的になる）．したがって，割合が小さいときに弱めるべきなのは「判定できない」の読みであり，当たりの読みではない．境を 40% と固定し，「この境を下回るコーパスの『判定できない』は『対照が目標をあまり変えなかったため』と書く」と直す．第 1 版の code の報告では #shufcl で変わる割合は MOSEI で 40% で，境のちょうど上下にある．
- [m4] 分け方の揺れの項は主の条件（K = 5，R1，#shufcl，全体）だけに足す（台本 `stage_summary` の `spv`）．副の R0 の区間にはこの項が無いので，R0 の区間は R1 より狭く出る．5 節の「R1 と R0 で判定が違う予言は『読み出しの作りに依る』と書く」を使うと，区間の作りの違いだけで判定が違い，それを読み出しの違いと書くおそれがある．R0 にも R1 の v_split を近似として足すか，R0 の区間は「分け方の揺れを含まない」と結果の表に書く．

## 確かめたこと

- 漏れ：評価のターゲットのテストの発話は読み込むが使わない（`dai3.Saved` の候補だけを使う）．R1 の主成分は候補の上でラベルを使わずに作る．C′ は目標の判断だけで選び，本当の感情のラベルを使わない（`fit_r1_multi` の内側の問は `tg_true` だけを使う）．本当の感情のラベルは入れ替えの層と，記述の Δ_s・P_s・uar_judge にだけ使う．台帳 242 行の「予言に使う 3×3 の再現できる度合いと入れ替えの対照の値は見ていない」と，試しで見た範囲（selftest，行数，所要，照合の差，summary の行数）は設計 0 節と合う．

- AFEW の扱い：`PRIMARY_3 = (P1, P3, P4a)` は AFEW を除いた 3 コーパスで 2 以上，ほかは 4 コーパスで 3 以上．`n_above_all4` も残す．設計 5 節と一致する．
- 予言の量：`PRED_DEF` の係数は設計 5 節の P1〜P4b と一致する．P4a・P4b の 4 項は同じ入れ替えの目標（生徒に依らない乱数）を共有する．
- R1 の選び方：K = 5 と 25 の目標を (K, 名前) の鍵で別に選ぶ．内側の分け方は学ぶ側の組を `pool_halves` で塊ごとに分けるので，内側でも塊は重ならない．同点は小さい C′．
- 再現性：`provenance.json`・`provenance_log.jsonl` にコミット，dirty，台本 6 本と設計と凍結のファイルと保存の入力の sha256，GPU，ソフトの版，格子，次元，乱数の種，引き直しの回数を残す．本番の置き場では未コミットの台本と設計を拒み，分割と種を絞れない．単位ごとの csv に実験 1 の単位のコミットを残す．同じコミットの単位は飛ばし，別のコミットの単位があれば止まる．summary は格子のそろいとコミットが 1 つであることを確かめる．
- 後からの解析への備え：npz に目標（真と各対照），交差の予測（R0・R1，K = 5・25，各分け方），出発点の判定，K 本だけの分類器の判定，確率の最大，2 組と別の分け方，K 本の印，共有の印，記号の印，sample_id を残す．性別ごとの内訳は sample_id を発話一覧につなげば出せる（第 1 版の code の報告が試した）．ただし M1 の対照は目標を作り直して学び直す必要があるので，保存からは出せない．このため計算の前に直す必要がある．
- 統計：区間の作り（塊の jackknife と種の項，MOSEI は共通の塊の重みの引き直し）は実験 1・12 と同じで，selftest に `dai1_stats.effect_stats` との一致がある．多重比較の補正をしないこと，コーパスの数え上げがコーパスをまたぐ検定でないことは 4 節と 9 節に書かれている．
