# 感情認識の査読者の検査：DAI-14（2026-11-12）

判定：条件つき OK

対象：設計 `DAI/docs/実験14_設計.md`（第 1 版），台本 `DAI/exp/dai14.py`（コミット 0e59a1b），台帳 `docs/seen-data.md` の DAI-14 の行，主張 `DAI/docs/主張_2026-11-12.md` 3 節．関門の報告（`DAI/checks/DAI-14/`）は，この検査の時点では 1 本も無かった．関門の報告がそろった後に，この報告と合わせて再検査する．

この実験は，主張 3 節の説明「声だけが，ほかのモダリティの手がかりを自分の中に持っている」を確かめるためのものである．感情認識の査読者の立場から見て，データの扱いに根本的な欠陥は無い．ただし，入れ替えの対照（本当の感情が同じ発話どうしで目標の判断を入れ替える操作）では取り除けない手がかりが 2 種類ある．1 つは 4 感情のラベルの中に残る感情の濃さで，もう 1 つは書き起こしに入っている声の手がかりである．どちらも，予言 P3・P4 が当たったときに「声に言葉や表情の中身が入っている」と読む根拠を弱める．どちらも，設計の文書を直し，保存する出力から計算する記述の解析を計算の前に足せば解ける．

## 重大な指摘

### [A1] 入れ替えの対照は「4 感情のラベルの中に残る感情の濃さ」を取り除かない
- 箇所：設計 3 節「入れ替えは『本当の感情ごとの J_m の分布』を保ち，発話ごとの対応だけを壊す」．同 3 節「発話ごとの分 D(s ← m) = R − R_shuf．特徴が感情しか知らないなら 0 に近くなる」．同 8 節は D に入る手がかりとして「話者，録音の環境，映像の場面」を挙げる．
- 問題：入れ替えで保たれるのは 4 つのラベルの単位の一致だけである．同じラベルの中にも感情の濃さの違いが大きく残っており，声の特徴はこの濃さ（特に覚醒度．興奮している度合い）をよく表すことが知られている．そのため，声の特徴が言葉の中身を持っていなくても，D(A ← T) は正になりうる．声が感情の濃さを顔や言葉より良く表していれば，P4 の 2 つの差も正になりうる．発話一覧で数えた値を示す（`data/metadata/*_utterance_manifest.csv`．評価の回の候補に絞る前の全体で数えた）．
  - IEMOCAP の即興：Happy の 947 発話のうち 663（70%）は元のラベルが excited で，284 が happy である．覚醒度の注釈（1〜5）の平均は excited で 3.58，happy で 3.22 になる．同じラベルの中の標準偏差は 0.51〜0.67 ある．
  - MOSEI：Neutral の 8,847 発話のうち 61.6% は，どれかの感情の強さが 0 より大きい（最大 0.33）．Neutral は「どの感情の強さも 0.5 未満」という残りの発話から決まるので，弱い Happy や弱い Sad が混ざっている．Happy の中でも強さの最大値は 0.5〜3.0 に広がる（標準偏差 0.55）．
  - MELD の `sentiment_raw` は 4 感情からそのまま決まる（Happy はすべて positive，Angry と Sad はすべて negative，Neutral はすべて neutral）．したがって MELD と AFEW には，ラベルより細かい注釈が無い．
  たとえば，K = 5 の言葉の分類器が IEMOCAP の excited の発話を Angry と判定し，happy の発話を Happy と判定する傾向を持つとする．このとき声の特徴は，覚醒度の違いだけを手がかりにして，Happy の中で J_T の判断を再現できる．この再現は D(A ← T) に入る．
- DAI の基準との関係：報告の誤りに当たる．設計 5 節は，P3・P4 が外れたときの書き方だけを決めている．当たったときの書き方を決めていないので，当たったときに「声に言葉の中身が入っている」と書かれるおそれがある．8 節の限界にも感情の濃さが無い．感情認識の査読者は「声は覚醒度を最もよく表す」という知見をもとに，最初にこの別の説明を挙げる．
- 直し方：
  1. （必須）設計 5 節に，P3・P4 が当たったときの書き方を足す．「声の特徴は，4 感情のラベルの一致を除いても，ほかのモダリティの判断と一致した．この一致には，ラベルの中の感情の濃さ（覚醒度など），話者，長さなど，感情の中身以外の手がかりが含まれうる」までにする．8 節の限界に，感情の濃さを数値の例とともに足す．
  2. （強く勧める．「可能な限り検証」という研究者の指示に沿う）IEMOCAP と MOSEI だけで，もっと細かい層の中で入れ替えた対照 R_shuf_fine を目標に足す．IEMOCAP は元のラベル（neu・hap・exc・sad・ang）× 覚醒度の 3 つの区分，MOSEI は 4 感情 × 強さの最大値の 3 つの区分にする．区分の境は候補の分布から計算の前に決める．`shuffle_within` に渡す層を変えるだけで済み，学習は判断 1 つにつき 1 つ増える．D_fine = R − R_shuf_fine を記述として出し，P3・P4 の結果の文で D と D_fine を並べる．MELD と AFEW には細かい注釈が無いので，この確かめができないことを書く．
  3. 2 を足さない場合は，1 の書き方と限界で済ませる．計算の後に足すと学び直しが要るので，足すかどうかは計算の前に決める．

### [A2] 言葉の特徴にも声の手がかりが入っている（書き起こしの記号と句読点）．主張の前提「言葉の特徴には声色も表情も入っていない」は，この実験では確かめられず，データとも食い違う
- 箇所：主張 3 節「言葉の特徴には声色も表情も入っていない」．設計 5 節の P1・P3（R(A ← T) を使う）．設計 6 節は R(T ← A) を記述として出すが，予言にも限界にも使わない．
- 問題：書き起こしには，声の出し方を表す記号や句読点が入っている．発話一覧で数えた値を示す（候補に絞る前の全体）．
  - IEMOCAP の即興：4,784 発話の 2.5% に `[LAUGHTER]`（115 件）があり，ほかに `[BREATHING]`（34 件）や `[GARBAGE]` もある．笑い声の印は Happy の手がかりになる．
  - MELD：30.5% に「!」がある．字幕の作り手は，話し方を聞いて「!」を付ける．
  - AFEW：16.8% に「!」がある．AFEW の書き起こしは Whisper large-v3 が音声から作るので，句読点も音声の抑揚から決まる．
  したがって J_T（言葉の分類器の判断）の一部は，声の出し方から来ている．声の特徴がこの部分を再現すると，P1 と P3 は「声が言葉を持つ」からではなく「言葉が声を持つ」から当たる．AFEW について設計 5 節は「声と言葉は同じ信号から来る」と注記しているが，MELD と IEMOCAP にも同じ向きの経路が小さく残る．
- DAI の基準との関係：報告の誤りに当たる．主張 3 節の「言葉の特徴には声色も入っていない」をこの実験の結果とともに書くと，確かめていない前提をデータに反する形で書くことになる．
- 直し方：
  1. （必須）設計 1 節か 8 節に「言葉の特徴に声色が入っていないという前提は，この実験では確かめない」と書き，上の数を限界として書く．結果の文と論文では，主張 3 節のこの文を使わない．
  2. （必須．計算のやり直しは要らない）記述の解析を設計 6 節に足す．内容は，書き起こしに「!」・`[LAUGHTER]` などの括弧の印が無い発話だけに絞って R(A ← T)，R(V ← T)，D(A ← T) と P1・P3 の量を出し，全体の値と並べることである．単位の npz は `sid` と交差の予測を保存しているので，発話一覧と `sample_id` で突き合わせれば summary の段だけで出せる．絞る規則（どの記号を印とみなすか）は計算の前に設計に書く．

## 軽微な指摘

- [a1] 設計 6 節は「MELD・IEMOCAP で 2 つの組が同じ対話を共有する発話を除いた版」と書くが，台本（`dai14.py` の `run_unit` と `stage_summary`）は MELD だけで計算する．IEMOCAP の塊はセッション（`dai_data.clusters` が `sample_id` の先頭 5 文字を使う）なので，2 つの組は対話を共有しない．台本は正しく，設計の文が誤っている．ただし IEMOCAP の即興の場面（impro01〜08 など）は，5 つのセッションで同じ筋書きを使い回している．このため，2 つの組が同じ筋書きの話題を共有する．設計の文を「MELD だけ」に直し，筋書きの共有を 8 節に書く（主張 2 節の「IEMOCAP の言葉は筋書きの話題の共有と分けられない」と同じ事情）．
- [a2] 発話の長さ：K = 5 の言葉の分類器は語の数に引っ張られうる（「Okay.」のような短い発話は Neutral になりやすい）．声の特徴は時間方向の平均だが，話す速さや無音の割合を通して長さを表しうる．`data/README.md` 1 節の 4 も，映像の特徴が長さの代理になった例を挙げている．8 節の限界に長さを足す．A2 と同じく summary の段で，`duration_sec` か `n_token` の 3 つの区分ごとに R と D を出す記述の解析を設計に書いておくとよい．
- [a3] 話者の性別：声も顔も性別を強く表す．J_T が性別と相関すれば，A ← T と V ← T の再現はどちらも性別を通して上がる．8 節の「話者」に性別を例として足す．AFEW の発話一覧には `gender` の列があり，IEMOCAP は話者 ID の F と M から性別が分かる．
- [a4] R は候補の全体で数えるので，J_m の学習に使った K 本（4 × 5 = 20 発話）も含まれる．そこでは J_m が本当のラベルとほぼ一致する．候補の大きさに比べると影響は小さいが，R を `nk`（K 本を除いた発話）に絞った版も出すか，含めることを文に書く．台本は `nk` を保存しているので，計算のやり直しは要らない．
- [a5] 先行研究との対応：
  - 「音声に言葉の情報が入っている」という説明には，最も近い感情認識の先行研究として Wagner ほか 2023（IEEE TPAMI．https://arxiv.org/abs/2203.07378 ）がある．要旨は，感情価（快・不快）の推定が良い理由を「微調整の間に Transformer の層が暗黙に学んだ言葉の情報」に帰している．`docs/related-work.md` 776 行と 1754 行の記録も同じ趣旨である．本実験の WavLM は微調整しておらず，最終層を時間方向に平均した特徴である（`data/README.md` の音声の節）．したがって，Wagner らの知見はそのままでは本実験の前提を支えない．この違いを結果の文に書く．
  - 自己教師ありの音声モデルの中で語の情報がどの層に多いかはモデルによって違う（Pasad ほか 2023，ICASSP．https://arxiv.org/abs/2211.03929 ）．最終層だけを使う本実験の結果は，層を変えると変わりうる．8 節に足す（DAI-13 で層の重みを扱ったことと矛盾しない書き方にする）．
  - 顔の判断を声の生徒が再現する P2 は，Albanie ほか 2018（顔の教師から声の生徒へ，ラベル無しで感情を移した研究）と同じ向きの量である．この研究を引いて比べる．
- [a6] AFEW の Whisper：映画の音楽や雑音の区間で，Whisper が声の無いところに定型の文を作ることがある．そうした発話では J_T が音声の非言語の部分から決まる．設計 5 節の「AFEW を除いた 3 コーパスの数え」で予言の判定は守られている．AFEW の値を記述として示すときは，`afew_transcript_whisper.csv` の `compression_ratio`（同じ文の繰り返しの印）と，`data/README.md` の繰り返しの疑いの 33 本に触れる．
- [a7] P1・P2 の差（R(A ← T) − R(V ← T) など）は，生徒になる各モダリティがもともと感情をどれだけ当てるかの差も含む．設計 5 節の書き方（「声の特徴はほかのモダリティの判断を最もよく再現した」まで）はこの点で正しい．結果の表では，`conditions.csv` の `uar_none`（各生徒の K 本だけの分類器の UAR）を P1・P2 の隣に並べる．
- [a8] MOSEI は話者の代わりにチャンネルか動画 ID の塊を使う．同じ人物の別の動画が 2 つの組に分かれうるので，話者の声と顔は 2 つの組をまたいで再現に使われうる（`data/README.md` 3 節）．8 節に書く．
- [a9] 感情ごとの解析：設計は感情ごとの主張をしないので，件数の不足は判定に関わらない．単位の npz は `y`・`tgt_*`・`pred_*` を発話ごとに保存しているので，査読で「どの感情で D が生じるか」と聞かれても summary の段で答えられる．感情ごとの値を論文に書くときは，感情ごとの件数と区間を付ける．

## 確かめたこと

- 役の定義 `DAI/.claude/agents/dai-review-affect.md`，`DAI/CLAUDE.md`，設計，主張の文書，台帳の行，台本の全文，`data/README.md` の 1 節と 3 節（ラベルの決め方，転写の出所，MOSEI の話者の代わり）を読んだ．`DAI/exp/dai3.py` の `pool_halves`・`disjoint_halves` と，非共有の版の計算（1085〜1087 行．MELD だけ），`DAI/exp/dai_data.py` の `clusters`・`dialogue`・`load_corpus` を読んだ．
- 評価のターゲットのテストの発話は使われない．台本が触るのは `dai3.Saved` の候補（`u.pool`）と K 本の分類器だけである．本当のラベルは，入れ替えの層と，当たる幅・真似できる分の計算にだけ使われる（`shuffle_within`，`cell_true`）．
- 2 つの組は塊ごとに，ラベルを使わずに分けられる．同じ塊（AFEW は俳優と映画をつないだ塊，IEMOCAP はセッション，MELD は話者，MOSEI はチャンネルか動画）が 2 つの組にまたがることは無い．
- コーパスの扱いは評価の回と同じである．IEMOCAP は即興だけ，MELD の複数の人の声と合同発話は落とし，AFEW と MELD の同じ人物の別名はまとめ，3 つのモダリティがそろう発話だけを使う（`load_corpus`）．顔を検出できなかった発話は 3 つがそろわないので候補に入らない．
- ラベルの対応は `data/README.md` 3 節のとおりである（IEMOCAP の excited は Happy に入れ，frustration は入れない）．文献の慣行（4 クラスの IEMOCAP）と合う．A1 で挙げた濃さの違いは，この対応から生じる．
- 主指標は UAR と同じ式の釣り合いの一致で，でたらめなら 25 になる．目標に現れない感情は平均から除かれる（`uar_present`）．
- 単位の npz は `sid`・`y`・`cl`・`half`・`nk`・`nonshared`・目標・交差の予測を発話ごとに保存する．そのため，A2・a2・a3・a4・a9 の記述の解析は，計算をやり直さずに summary の段で出せる．A1 の 2 だけは学習を足す必要がある．
- データの申告：新しいデータを使わず，保存済みの出力を解析し直すだけである．利用条件と倫理の申告は，評価の回のものがそのまま当てはまる．
- 計算はしていない（査読の役は台本を読むだけ．試走は gate-code の担当）．
