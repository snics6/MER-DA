## 重大な指摘

### [M1] 確率の配列の名前に版が入らず，真の目標の確率が対照の確率で上書きされる
- 箇所：`DAI/exp/dai14.py` 465〜472 行
  ```
  def add_rows(K, ro, s, res, split, tgt_frac):
      for (nm, ver), (full, ag, info) in res.items():
          arr[f"K{K}__{split}__{ro}__{s}__{nm}__{ver}"] = full
          ...
          if K == K_MAIN and split == "main" and info.get("prob") is not None:          # 全部の版（gate-code の第 3 版の H1）
              arr[f"prob__K{K}__{split}__{ro}__{s}__{nm}"] = info["prob"]
  ```
  と，設計 3 節「確率：K = 5，元の分け方の交差の予測の確率（float16）を，R0・R1 の全部の版（真と各対照）で保存する」．
- 問題：第 3 版では `ver == "true"` の条件があったので，名前 `prob__K5__main__R1__A__single_T` には真の目標の確率だけが入った．第 4 版はこの条件を外したが，名前に `ver` を足していない．`res` は 1 つの目標の名前 `nm` について版を `true → shuf → shufcl → (shuffine か shufage)` の順に並べるので（R0 は `tg0`，R1 は `R1_ALL[s]` の作りの順），同じ名前に 4〜5 回書き込まれ，最後の版の確率だけが残る．たとえば IEMOCAP の声の生徒が言葉の判断を再現する確率の配列には，真の目標ではなく #shuffine の目標で学んだ識別器の確率が入る．配列の名前は真の目標の確率に見えるので，後から「argmax の代わりに確率で測った D」（設計 3 節）を出すと，D = 真 − 対照のつもりで「#shuffine − #shufcl」に近い量を計算し，誤った値を報告する．第 3 版で出せた真の目標の確率も失われる．
- DAI の基準との関係：主の判定（argmax の一致による R と D）には関わらない．ただし保存した出力から出す後の解析が誤った値になるので，報告の誤りの原因になる．計算の後に気づくと約 5 時間の計算をやり直す必要がある．
- 直し方：名前に版を足す（例：`arr[f"prob__K{K}__{split}__{ro}__{s}__{nm}__{ver}"] = info["prob"]`）．設計 6 節の保存の説明（「交差の予測の確率（K = 5，元の分け方，真の目標，R0・R1．float16）」）も第 4 版の作り（全部の版）に合わせて直す．selftest か試しの段で，1 つの単位の npz の `prob__` の名前の数が「生徒 × 目標 × 版 × 読み出し」の数になることを確かめると，同じ種類の誤りを防げる．

## 確かめたこと

- **感情ごとの 3 区分（#shuffine）**：`tertile_within(v, y)` は本当の感情ごとに，単位の候補の上で有限の値だけから 3 分位を取り，欠けを "na" にする．層は #shufcl の層（感情，塊，性別）の後ろに区分をつなぐので入れ子のまま．テストの発話は使わない（`meta` は候補に並べ直した表）．
- **#shufage**：AFEW だけ．俳優の年齢 `actor_age` を候補の上の 3 分位（感情をまたいで共通の境．欠けは "na"）で分け，#shufcl の層にさらにつなぐ．設計 3 節の「候補の上の 3 分位．欠けは別の区分」と合う．発話一覧で `actor_age` の欠けは 1,156 本のうち 4 本で，年齢の数が 2 つ以上ある俳優は 44 人（作品ごとの年齢）なので，俳優の中でも区分が変わりうる．層を細かくすると frac_changed が下がって D が 0 に寄るので，この規則は「上回る」を数えにくくする向きに働く（主張に有利な偏りは入らない）．`share_singleton_age` を単位の csv に出す．
