### [M2] 要件 3 の「表せる分」は候補の上の当てはめの成績で，候補の本数 n が次元 d 以下のコーパスでは作りの上で出所に近づく．R3 の「取り込める割合 0.5 未満の数」と見込み (d) がこの作りに左右される
- 箇所：
  - 設計 3.3 節（「出す量は，交差検証の決定係数 R²，当てはめた予測の argmax の nk の上の UAR（`UAR_proj`），`UAR_proj` − K 本だけの版の UAR，取り込める割合 (UAR_proj − UAR_none) / Δ（Δ ≥ 0.5 のときだけ）」）
  - 設計 4 節 R3（「Δ ≥ 5 なのに得 < 0.5 のセルの数と，そのセルで取り込める割合が 0.5 未満の数を書く（要件 3 の読み）」），見込み (d)（「得と最も並ぶのは Δ ではなく `UAR_proj` − UAR_none（表せる分）」）
  - 台本 186〜210 行（`representability`：λ は塊で分けた 2 つの半分の交差検証で選ぶが，返す `Yhat` は候補の全発話で当てはめた予測），312 行（`pp = Yhat[...].argmax(1)...[nk]`：当てはめに使った発話そのものの上で測る），316 行（`share` を単位ごとの比で出す），452 行（単位ごとの比を `mean` で平均）
- 問題：
  1. **当てはめに使った発話の上の成績である．**リッジ回帰（係数の大きさに罰則を付けた最小二乗の当てはめ）を候補の全発話で解き，その同じ発話の上で argmax を取っている．候補の本数 n が次元 d 以下なら，罰則が弱いとき当てはめは出所の値をほぼそのまま再現するので，`UAR_proj` は出所の UAR に，取り込める割合は 1 に近づく．これは特徴が出所の直しを「表せる」からではなく，未知数が式の数より多いからである．λ は交差検証で選ぶので罰則が 0 にはならないが，選ばれる λ の大きさと当てはめの近さは n/d で大きく変わる．
  2. **該当するセルが多い．**学び直す分類器の次元は音声 1,024，顔 512，言葉 768，融合 2,304 である．候補の本数はおおよそ AFEW 630，IEMOCAP 2,350，MELD 8,500，MOSEI 14,900 である（DAI-1 の設計と DAI-8 の検査の数から．値は見ていない）．n/d は AFEW で音声 0.6，顔 1.2，言葉 0.8，融合 0.3，IEMOCAP の融合で約 1.0 である．AFEW の 4 つの学び直す分類器すべてと IEMOCAP の融合で，取り込める割合は作りの上で 1 の近くに寄る．一方 MOSEI（n/d 6〜29）では寄らない．コーパスをまたいで割合を並べる R3 の数え上げと順位相関は，この違いを「表せる分の違い」として読んでしまう．
  3. **前の実験の同じ量と作りが違う．**表せる分の上限の前の設計（`docs/exploratory-analyses.md` の E85．2026-11-03）は，当てはめを候補で解き，成績は**テスト**（当てはめに使っていない発話）の上で測り，λ は候補の 2 分割の保留側で選び，n/d を出力に残すと決めた．この決まりは関門の目録の D17（上限として読む当てはめは，ラベルを使わずに選んだ正則化で行い，忠実さ・収束・n/d を出力に残す）になっている．今の設計は λ の選び方だけを受け継ぎ，成績の測り方（当てはめに使っていない発話で測る）と n/d の出力を落としている．設計 8 節の限界（「学び直しの解が当てはめの解に近いという前提は測らない」）はこの点を書いていない．
  4. **割合を単位ごとに割ってから平均している．**`share` は単位ごとに (UAR_proj − UAR_none)/Δ を出し，Δ < 0.5 の単位を NaN にして，セルの平均は NaN を除いた単位だけで取る（`Rc = R.groupby(...).mean()`）．関門の目録の D18（同じ分母の割合どうしを比べる判定は，分母が打ち消し合う量で書き，割ってから平均しない）に反し，セルごとに平均に入る単位の数も出力に残らない（`n_units` は全単位の数）．
- DAI の基準との関係：報告の誤りに当たる．R3 の「Δ ≥ 5 なのに得 < 0.5 のセルで取り込める割合が 0.5 未満の数」は，小さいコーパスでは作りの上で 0 に寄るので，「要件 3 は満たされていた（表せない分が理由ではない）」という読みを根拠なく支えうる．見込み (d) の判定も同じ作りに乗る．
- 直し方：
  1. 台本 `representability` で，λ を選んだ後に，**当てはめに使っていない半分での予測**（半分 h の発話には h 以外で当てはめた係数を当てる）も返す．交差検証のループで `ridge_predict(X[te], B)` はすでに計算しているので，選んだ λ の列だけ保存すれば足りる（当てはめの回数は増えない）．これを `UAR_proj_oof`，`proj_gain_oof`，`share_oof` として段 1 の行に足す．今の候補の上の値も残し，名前を `UAR_proj_in` などにして区別する．
  2. 段 1 の行に n（候補の本数）と d（学び直す分類器の次元）と n/d を書く（D17）．
  3. 設計 3.3 節に，2 つの量の意味を書く：候補の上の値は「この候補の点の上で線形の関数が出所の判定をどこまで再現できるか（n ≤ d では作りの上で高い）」，当てはめに使っていない半分の値は「同じコーパスの別の塊に通じる再現の度合い」．R3 の順位相関と「取り込める割合 0.5 未満」の数え上げは，計算の前にどちらで数えるかを 1 つに決めて書く（E85 と関門の目録 D17 に合わせるなら，当てはめに使っていない半分の値）．もう一方は並べて記述する．
  4. 取り込める割合は，セルの平均の `proj_gain` をセルの平均の `delta_uar` で割った値を主にし（D18），単位ごとの比の平均を出すならその平均に入った単位の数を列に残す（D11）．
  5. 8 節の限界に「当てはめの λ の選び方は学び直しの引き戻しと違うので，表せる分は学び直しが実際に受け取る分の上限の目安である」と書く（E85 と同じ文）．

## 確かめたこと

- **評価のデータの漏れ**：単位は DAI-1 の仮のターゲットの回の 120 単位（評価のターゲット T × 仮のターゲット c × 分割 × 種）で，台本は T のデータを読まない（`srcs = CORPORA − {T, c}`，`Both.get(c)`）．評価の回の保存（`results/dai1/eval/`）は読まない．第 2 エンコーダのソースの分類器は 4 コーパスすべてで作るが，単位では c と T を除いた 2 つだけを出発点に使う（DAI-1 と同じ）．候補のラベルは段 1 の測定（`yk = u.ypool[nk]`）と K 本（`gK`）にだけ使い，リッジの λ はラベルを使わずに選ぶ（`half` は塊の名前で分ける）．テストのラベルは判定の照合と集計にだけ使う．
- **DAI-1 との整合**：`none` は DAI-1 の段 1 の保存の W・b を，この台本で作り直した標準化の特徴に当て，判定の不一致が max(1, 0.1%) を超えたら止まり（247〜248 行），K = 0・5 では候補の確率の最大の差も 0.02 を超えたら止まる（250〜257 行）．学び直しの形は DAI-1 の `ret`（K 本の釣り合いの one-hot ＋ 感情ごとの総量をそろえた疑似ラベル，総量 n，引き戻しは (種類, max(K, 1))）と同じ（`pass2` の 285〜289 行と台本 329〜332 行を比べた）．`other` の積は `dai1.product` の指数 (1,1,1) と同じ（自己検査にも入っている）．コミットの照合は `pseudo_commit` と各 npz の `commit`（227〜229 行）．
- **4 つの出所と学び直しの対応**：`TEACHERS` と `teacher()` は設計 3.1 節のとおり（AVT には `enc2fuse` を与えない）．`enc2` の K ≥ 1 は第 2 エンコーダの出発点から K 本だけで学び直す（277〜279 行）．`enc2none` のテストの判定も K ごとに残す．
- **統計**：UAR の差は `dai1_stats.effect_stats` で，(f, r) を単位に 3 つの T の数を平均してから塊の jackknife（AFEW・IEMOCAP・MELD）か塊の引き直し（MOSEI）に種の項を足す．DAI-8・10 で通った作りと同じ．ほかの指標は分割ごとの平均の t（自由度 4）で記述．R1・R1′・R2 の数え上げ（区間の下端 > 0 かつ点推定 ≥ 0.5 を 3 つ以上の K）と MOSEI の channel の添え書きの数え方は設計 4 節と一致する（480〜498 行）．K が同じテストと候補を共有することは設計が書いている．
- **保存と集計**：テストの発話ごとの判定（int8）を (K, 生徒, 出所) ごとに残し，感情ごとの再現率・WAR・WAF・macro-F1 は集計で作る．`uar_units.csv` に単位ごとの値が残るので，感情ごと・分割ごとの内訳は後から出せる．出力先が既にあれば止まり，未コミットの変更があれば止まる（`--allow-dirty` は起動の台本が渡さない）．
- **比較相手の選び方**：この試しは手法の提案ではなく解析で，設計 0 節と先行研究の差分の報告（0 節「手法として新しいとは書けない」）がそう位置づけている．標準の手法の相手は要らない．`self` が「新しい情報を持たない対照」として置かれている．
- **見たデータ**：台帳 185〜186 行の記述（ファイル名，発話の数と分割の一致，npz の鍵，所要の列，前の実験の候補の上の値）は，設計の判断に評価の値を使っていないことと矛盾しない．
- **DAI の基準で判定しないこと**：この試しの重要さと新しさは判定に使っていない．
