## 判定
直してから通す．評価のターゲットのラベルはこの実験の選ぶ段にも仮のターゲットの回にも入らず，テストと学習側の話者・塊・対話の重なりは 0 件と数えたが，手法の部品の多くを前の実験で同じ 4 コーパスの評価の成績を見てから決めた経緯が設計の文書と台帳に部品ごとに書かれておらず，固定してから評価を 1 回だけ回す順序を台本が確かめていないので，この 2 点を計算の前に直す必要がある．

## 依頼で挙がった 5 点の確認の結果

1. **選ぶ段が評価のターゲットの出力を読まないこと**：満たす．`dai1_select.py:40` は `out/pseudo/units/{T}_*_p{1,3}.csv` だけを読み，`dai1_select.py:90` は `out/pseudo/{T}_tether_w.json` だけを読む．評価の回の出力は `out/eval/units/{T}_ALL_...` に書かれる（`dai1.py:364-365`）ので，選ぶ段の glob に当たらない．引き戻しの強さ（`dai1.py:394-401`）とモダリティの指数（`dai1.py:404-414`）を選ぶ処理も，仮のターゲットの回の行だけを読む（`dai1.py:453-456`）．評価の回では `select_tether` と `select_w` を呼ばず，固定のファイルの値を使う（`dai1.py:467-470`）．
2. **仮のターゲットの回にターゲットのテストが入らないこと**：満たす．`units_for`（`dai1.py:349-355`）は c を評価のターゲット T 以外の 3 コーパスから取り，ソースを c と T 以外の 2 つにする．`Unit` は c のコーパスだけを読み（`dai1.py:144`），出発点は 2 つのソースの識別器の平均である（`dai1.py:158-159`）．T の特徴もラベルも，T を除いたソースの識別器も，仮のターゲットの回には入らない．
3. **テストと学習側の塊・対話・話者の重なり**：分割の表（`DAI/splits/*.csv`）と発話一覧の `speaker_id` を突き合わせ，5 分割それぞれでテストと候補（`pool_mask` と同じ規則で作った学習側）の重なりを数えた．4 コーパスとも，塊の重なりは 0，`speaker_id` の重なりは 0，MELD の対話の重なりは 0 である．台本が実行時に作る分割（`dai_data.load_corpus`）は分割の表と完全に一致した．ただし，名前の違う同じ人物が分割をまたぐ例が MELD に 8 発話，同じ切り出しが 2 つの動画 ID で入る例が MOSEI に 1 組ある（下の [L5]）．
4. **標準化と中心化にテストの発話が入らないこと**：満たす．単位ごとの標準化は候補（テストを含まず K 本を含む）の平均と標準偏差で行う（`dai1.py:155-156`）．ソースの識別器の交差検証では，各分割の学習側の統計で標準化する（`dai1.py:106-108`）．ソースの識別器の最後の学習はそのコーパスの全発話の統計を使う（`dai1.py:114`）が，ソースは評価のターゲットではない．疑似ラベルの感情ごとの総量をそろえる処理（`dai_solver.py:47-52`）は予測の確率だけを使い，候補のラベルを使わない．
5. **K 本の抜き方が評価のターゲットに依らないことの影響**：抜き方は `common.rng_for("dai-K", コーパス番号, 分割, 種)` と，コーパスと分割だけで決まる候補から作る（`dai_data.py:114-122`）．2 回呼んで同じ K 本が出ることを 4 コーパスで確かめた．このため，コーパス X の評価の回の種 0・1 は，X をほかの 3 つの T の仮のターゲットにした回と同じテストの塊と同じ K 本を使う（出発点だけが違う．仮のターゲットの回はソース 2 つ，評価の回はソース 3 つ）．X の設定は X 以外のコーパスで選ぶので，X の評価の値に X のラベルは入らない．漏れとしての影響は無い．一方，「4 コーパスのうち x で」とまとめる文では，ある T の設定を選ぶのに使った値と，別のコーパスの評価の値が同じ標本の上にある．これは独立性の問題なので `gate-stats` に回す．
