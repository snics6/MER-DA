## 指摘

### [S2][S3] `detect` の種の数 R の規則は，IEMOCAP では種の項の割合を 0 と測るので，R = 10 を作りの上で選ぶ
- 重さ：直してから進む
- 該当箇所：`DAI/exp/dai1_stats.py:338-346`，`:213`，`:219`．設計 217-218・240 行
- 問題：R の規則は「K > 0 のセルの中央値で種の項が分散の 25% 以下になる最小の R」である（設計 218 行）．台本は種の項の割合を `vs / (r.v_jk + vs)`，`vs = r.v_seed * 2 / R` で測る（`:341-343`）．`r.v_seed` は `effect_stats` が返す `v_seed_kept`（`:213`）で，二重の数えを避けるために，塊を除くと分割ごと外れる分割の種の項を除いた値である．IEMOCAP では D が 5 分割の全部なので `v_seed` = 0 になり，全部のセルで割合が 0 になり，X = IEMOCAP の R はいつも 10 になる．種の揺れは消えたのではなく，V_jk の中に「(1/5)·平均(σ_f²/2)」として入っている（仮のターゲットは種 2 つ）．合成の数（塊 = 分割，分割の間の真の差なし，R = 10）では，V_jk = 1.459 のうち種の分は `v_seed_all` = 0.776 で 53% だったが，台本の測る割合は 0 だった．AFEW も分割 0 の種の項を割合から落とすので，割合を小さく測る向きである．
  - R は評価の回の前にしか決められない．評価の後に種を足すと，結果を見て単位の数を決めたことになる．IEMOCAP は自由度 3 で記述に回る見込みのセルが多いので主張への影響は小さいが，設計 218 行の規則の目的（種の揺れを分散の 4 分の 1 以下にする）が IEMOCAP で働かない．
- 計算の後で直せるか：`detect` の前なら直せる（台本の数行）．評価の回の後は直せない．
- 求める対応：R の規則に限り，種の項として `v_seed_all`（全分割の s_f²．`:219` ですでに返している）を使い，塊の項を `max(0, v_jk − v_seed_all)` とする（D の分割では V_jk に同じ大きさの種の項が入っているため）．すなわち割合を `v_seed_all·2/R ÷ (max(0, v_jk − v_seed_all) + v_seed_all·2/R)` で測る．検出できる差の見込み（`:350-352`）は設計 217 行のとおり保守の向きのままでよい．設計 218 行に「IEMOCAP と AFEW の分割 0 では，種の項を V_jk から引いて割合を測る」と 1 文足す．

### 記録 5 [S2] 族 3 の書き方の規則は，コーパス単位の条件とセル単位の主張の対応が書かれていない
- 該当箇所：設計 251 行，`DAI/docs/実験2_設計.md:105`
- 問題：規則は「そのコーパスで族 3 の差が Holm の補正の後に有意で，かつ『提案 − xMUDA 型』が 9 セルの過半で上回る」ときに「同じ情報を受け取る相手より良い」と書く．族 3 は 12 セルあるので，「族 3 の差が有意」がどのセルを指すか（1 つでも，過半か，その文を書くセルか）が書かれていない．セルごとに文を書く場合，過半の条件を満たしたコーパスでは，xMUDA 型との差がそのセルで「下回る」ときでも文を書けてしまう．差が無いときに偽の文が出る見込みは小さい（9 セル中 5 セル以上が片側 2.5% で偶然に「上回る」確率は 1.1×10⁻⁶）ので，向きは保守的である．
- 求める対応：「文はセル（生徒 A・V・T，K）ごとに書き，そのセルで族 3 が Holm の後に有意で，そのコーパスで 9 セルの過半が『上回る』で，かつそのセルの xMUDA 型との差が『下回る』でないときに限る」のように，単位をそろえて書く．評価の回の前に決める．
