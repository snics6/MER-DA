### [v2-1] bash 5.0 以前では，`wait -n -p` が使えず，台本が起動の直後に止まる．このとき処理を残し，印を書かない
- 重さ：直してから進む
- 該当箇所：`DAI/run/dai_eval.sh:72`（`wait -n -p fin; st=$?`），`:74`（`fail "処理 $fin が失敗（終了コード $st）"`），`:17`（`set -u`）
- 問題：`wait` の `-p` は bash 5.1 で入った．使えない版では `wait` が「invalid option」で 2 を返し，`fin` が設定されない．すると 74 行の `$fin` の展開で `set -u` に当たり，台本が `fail` を呼ばずに終わる．`wait` に知らない選択肢を渡す形で写して確かめた（`code_run_v2/waittest3.sh`）．出力は `fin: unbound variable` で，`.failed` も `.done` も書かれず，背景の処理 2 本は動き続けた．計算は失われないが，実験 3 の起動の条件（`.done`）が満たされない．計算の後の点検でも，処理が止まったのか終わったのかが印から分からない．研究室の PC の bash は 5.2.21 で，8 台の Pod の bash の版は分かっていない．
- 計算の後で直せるか：計算は続くので値は失われない．ただし台本を流し直すと，同じ単位を 2 本の処理が書く（第 1 回の [I-fail] と同じ状態になる）．
- 求める対応：25 行の前に `[ "${BASH_VERSINFO[0]}" -gt 5 ] || { [ "${BASH_VERSINFO[0]}" -eq 5 ] && [ "${BASH_VERSINFO[1]}" -ge 1 ]; } || { echo "bash 5.1 以上が要る" >&2; exit 1; }` を足す．あわせて 74 行を `${fin:-?}` にする．台本を変えないなら，8 台で `bash --version` を流し，5.1 以上であることを起動の前に確かめる．
