  1. 仮のターゲットで MOSEI の声の分類器に off が選ばれると，`dai15.py:371` で sel は prop そのものになり，sel − prop は効果 0・区間 [0, 0]・「判定できない」になる．このとき H3 の後半の条件は作りの上で満たされ，oracle − I が上回るだけで「推定の不足」と書くことになる．しかし off が選ばれた原因は，仮のターゲットの 3 コーパスで λ = 0・0.5 の版が I を平均で上回らなかったことであり，MOSEI の K 本の表の推定が足りなかったことではない．MOSEI の評価の回では λ = 0 の版が I を上回っていても，この規則はそれを見ない．
  2. 規則は「全ラベルの表の版」と「K 本の表の版」の差を直接比べていない．oracle − I は全ラベルの表で上がる余地，sel − prop は選んだ版と保存の提案の差で，2 つの差は基準（I と prop）も版の選び方（固定と選択）も違う．たとえば oracle − I が +0.5，sel − prop が +0.2（区間が 0 をまたぐ）のとき，規則は「推定の不足」と書くが，全ラベルの表と K 本の表の差（+0.3 前後）が区間で 0 と区別できるかは確かめていない．MOSEI の声の区間の半幅は約 0.24〜0.36 点（設計 48 行）なので，この差は区間の中に入りうる．
  3. 「上回らない」は区間が 0 を含むことでも満たされる．MOSEI は区間が最も狭いので前回の H4 ほどではないが，「推定の不足」という原因の主張を，効果が検出されなかったことから導く形は残る．
- 計算の後で直せるか：直せない（原因の帰属の規則を結果の後に変えると事後の選択になる）．今は評価の回の前なので，設計を直せば足りる．比べる差は保存の予測（`pred_K{K}_{s}_{0.0, oracle, I}`．`dai15.py:251`）から summary の段で作れる．
- 求める対応：
  1. H3 を選択を含まない固定の版どうしの差で書き直す．たとえば「MOSEI の声の分類器で，oracle − λ0 が上回り（全ラベルの表は K 本の交差の推定の表より上がる．どちらも λ = 0 で同じ重みの合わせ方），かつ oracle − I が上回るときだけ『K 本の表の推定の不足』と書く．oracle − I が上回らないときは『全ラベルの表でも上がる余地は検出できなかった』と書き，推定の不足に帰さない．oracle − λ0 が上回らないときは『全ラベルの表と K 本の表の差は検出できなかった』と書く」．
  2. `CONTRASTS` に `("oracle", "lam0")` を足す（`dai15.py:342-343`）．あわせて `("oracle", "sel")` を足すかを決める．

  4. 設計 20 行の「その形で切り分ける」を，上の規則に合わせて書き直す．
