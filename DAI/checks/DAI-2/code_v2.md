## 指摘

### [記録 1] 仮のターゲットの回の勾配法の所要が設計 2.3 節の削り方のしきい値（12 時間）をまたぐ
- 重さ：記録する（起動の前に決めること）
- 該当箇所：設計 2.3 節「予算を超えたときの削り方」，5 節「束の大きさを変えた解き直しで 1 割ほど増える」
- 問題：解き直しを足した後の見積もりは H200 で 10.2〜13.6 時間で，上の端が 12 時間を超える．削り方は全部の単位で同じでなければならない（選ぶ段が単位ごとの削り方の違いで止まる）．そのため，削るかどうかは起動の前に決める必要がある．また，12 時間が GPU の時間の合計か，2 台の pod で並べた経過時間かが設計に書かれていない．5 節の「1 割ほど」は，測った +16%（評価の回は約 +30%）と合わない．
- 求める対応：仮のターゲットの回の前に H200 で 1 単位（map・xmuda・coral）を測り，12 時間の意味を設計に書いてから削り方を決め，5 節の増分を測った値に直す．

### [記録 2] xMUDA 型の解き直しの行に，その生徒の比べに使わない行が混ざる
- 重さ：記録する
- 該当箇所：dai2_grad.py の `pass_xmuda`（解き直しの点を 3 つの生徒で共有し，全部の生徒に行を書く）
- 問題：xMUDA 型は 3 つの生徒を同時に学ぶので，V だけが選んだ点も A の行として書かれる．A の mapctl はその点を解き直さないので，A の行の dis_ctl_rep は NaN になる（試走で 16 行中 3 行）．値の誤りではない．
- 求める対応：基準を当てる集計では，roles に `selected_<その生徒>` か `ref` を含む行だけを使うことを，台本の冒頭の説明か設計 2.3 節に書く．

### [記録 3] xMUDA 型の解き直しの点 XM_REF が設計に無い
- 重さ：記録する
- 該当箇所：dai2_grad.py の `XM_REF`，設計 2.3 節「各単位の選択なしの点（評価の回ではさらに選んだ点）」
- 問題：xMUDA 型には選択なしの値が無いので，仮のターゲットの回の解き直しの点（学習率 1e-3・反復 1000・κ 1・μ 1）は台本が決めている．設計の文からは読み取れない．
- 求める対応：設計 2.3 節にこの点と理由（mapctl の選択なしの値と同じ学習率・反復・μ，κ は候補 1 本あたり 1）を 1 文で書く．
