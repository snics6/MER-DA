データの扱いの骨組み（IEMOCAP は即興だけ，ラベルは発話一覧から貼り直す，テストの塊は候補に入らない，MELD はテストの対話を候補から除く）には欠陥が無い．
重大な指摘は 2 つある．どちらも「蒸留は単独の分類器どうしの依存を増やす」という 4 コーパスにまたがる文に，コーパスに固有の共有の要因（IEMOCAP 即興の筋書きの話題，MOSEI の同じ人物の別の動画）が入りうるのに，判定の規則がそれを分けないことである．どちらも集計の段と設計の文を足せば解け，単位の段（`run_unit`）の計算を変える必要は無い（必要な配列は `fits/` に保存される）．

この報告で使う語：
- **蒸留**：ほかのモダリティを含むモデルの予測（疑似ラベル）を目標にして，単独のモダリティの分類器を学び直すこと．設計の joint と joint_a1 がこれにあたる．none は蒸留しない分類器（ターゲットのラベル K 本だけで学ぶ）である．
- **依存 D**：同じ感情のラベルを持つテストの発話の中で，2 つのモダリティの分類器の点数がどれだけ一緒に動くか（正準相関の 2 乗の平均から偶然の水準を引いた量．設計 3.3 節）．ΔD は 2 つの分類器の組の D の差である．
- **筋書き**：IEMOCAP 即興で演者に与えた場面の設定（8 種類）．場面は特定の感情を引き出すように作られている．
- **塊**：テストと学習側を分ける単位（IEMOCAP はセッション，AFEW は俳優と作品のつながり，MELD は話者，MOSEI はチャンネルか動画）．区間は塊を抜き直して作る．
- **区間**：塊を抜き直して作った 95% の範囲．

## 重大な指摘

### [A1] IEMOCAP 即興の筋書きの話題の共有を分ける量が無く，「言葉と言葉を含む識別器の文は IEMOCAP 即興を含めた数と除いた数の両方で書く」という DAI の既定が判定の規則に無い
- 重さ：重大（計算の前に，判定の規則と集計の段の出力を直す）
- 箇所：
  - 設計 4 節 H1「4 コーパスのうち 3 つ以上で満たせば，「蒸留は単独の分類器どうしの依存を増やす」と書く」．H1′・H2・H3 と前提 (iv) も同じ数え方である．
  - 設計 3.3 節「D = 3 つの組の D(m, m′) の平均」．3 つの組のうち声と言葉，顔と言葉の 2 つが言葉を含む．
  - 設計 3.2 節「主の版も 4 コーパスと 5 K のすべてで `one` である」．教師はどのコーパスでも声・顔・言葉の 3 つの分類器の積で，言葉を含む．
  - 計画 8 節（統計）「言葉と言葉を含む識別器についての文は，IEMOCAP 即興を含めた数と除いた数の両方で書く（A1）」，代わりの説明の表の IEMOCAP の行（筋書きの中の対で分ける），8 節（重なり）「IEMOCAP 即興の 8 つの筋書きは複数のセッションで演じられる」．DAI-6 は同じ既定を `proceed_excl_IEMOCAP` として判定に入れた（`DAI/checks/DAI-6/review_affect_v3.md`）．
- 問題：
  - 本検査が `DAI/splits/IEMOCAP.csv` の `label_4` と `sample_id` の筋書きの番号で数えると，テストの各セッションには 7〜8 個の筋書きが出る．Neutral の発話は 1 つのセッションの中で 6〜8 個の筋書きに散らばる（例：分割 0 の Neutral 287 本は筋書き 04 に 82 本，05 に 77 本，08 に 79 本，ほかに 49 本）．Happy の 96.6% は筋書き 03・07，Sad の 96.8% は 02・06 にある（DAI-6 の検査が分割 0 の候補で数えた値）．
  - このため，同じ Neutral のラベルの発話の中でも，話題（例：筋書き 05 は Angry と Neutral の場面）が発話ごとに違う．言葉の分類器は話題の語を読める．教師は言葉の分類器を含む積なので，Neutral の発話に筋書きごとに違う確率を付けうる．声と顔の生徒は，候補の発話（同じ 8 つの筋書きを演じた別のセッション）でこの目標に合わせて学ぶ．その結果，テストで同じ筋書きの発話の点数が声と言葉で一緒に動けば，D は増える．このとき増えた依存の中身は感情の表し方ではなく筋書きの話題である（推測．大きさは測っていない）．
  - 設計の副の量のうち，話者で中心化した版は IEMOCAP を `speaker_id` で中心化する．1 人の話者は同じセッションの中で複数の筋書きを演じるので，この中心化は筋書きの共有を除かない．教師の点数を除いた版（D_t）は，増加が教師の写しかどうかを分けるが，写したものが筋書きの話題かどうかは分けない．
  - IEMOCAP の区間は 5 つのセッションの抜き直しで作る．人工のデータで本検査が確かめると，5 つの値の抜き直しの 95% 区間は，自由度 4 の t の区間の幅の約 0.62 倍で，真の平均を含む割合は約 84% だった（`--selftest` とは別に，正規分布の 5 つの値で 4,000 回流した）．4 つの K は同じ 5 つのセッションを共有する．このため IEMOCAP は「区間の下端 > 0」を満たしやすく，その合否が「4 コーパスのうち 3 つ」の判定を左右しうる．
  - 交差の当てはめ（設計 3.5 節）は IEMOCAP のすべての分割で発話の単位で分かれる．2 つの半分は同じ対話と同じ筋書きを共有するので，H3 の L_dep にも筋書きの共有が入る．
- DAI の基準との関係：主張と証拠の対応の欠陥であり，DAI の計画の既定からも外れる．IEMOCAP が 3 つ目のコーパスになったとき，「蒸留は依存を増やす」という文は筋書きの話題で増えた分を含む．感情認識の査読者は，IEMOCAP 即興の話題と感情の結びつきを既知の問題として指摘しうる．
- 直し方（どれも `fits/` の z・`test_sample_id`・`test_y` から作れ，単位の段の計算は変えない）：
  1. `criteria.csv` に，H1・H1（joint）・H1′・H2・H3 と前提 (iv) の全体の数を，IEMOCAP 即興を除いた 3 コーパスで数えた列（例：`H1_n_excl_IEMOCAP`）を足す．4 節に次の書き方を足す．全体の文は「4 コーパスのうち x（IEMOCAP 即興を除くと 3 つのうち y）」と書く．4 コーパスで 3 つ以上を満たし，IEMOCAP 即興を除くと 2 つ以下になる規則では，「この判定は IEMOCAP 即興の合否に依り，IEMOCAP 即興の依存の増加は筋書きの話題の共有と分けられない」と書く．
  2. 3.3 節に，IEMOCAP の副の量として「筋書きで中心化した D」を足す．テストの点数から（筋書き, 感情）ごとの平均を引き，偶然の水準は（筋書き, 感情）の中の並べ替えで作る．筋書きは `sample_id` の `impro` の後の 2 桁で数え，05a・05b は 05，08a・08b は 08 とする（実験 3 の設計 3 節の 5 と同じ）．3 本未満の（分割, 筋書き, 感情）の発話は外し，外した数を残す．本検査の数えでは，どの分割と感情でも発話の 95.5% 以上が 3 本以上のセルに入る．ΔD と同じ抜き直しで区間を付け，記述とする．
  3. 言葉を含まない声と顔の対（AV）の ΔD について，H1 と同じ数え方の結果を `criteria.csv` に記述として足す（値は `diffs.csv` の `pair` の列にすでにある）．4 節に「声と顔の対だけでも満たすか」を並べると書く．
  4. 0 節の (e) に，出どころ（感情認識の査読者の A1）とともに書く．

### [A2] MOSEI の話者の分離が不完全であることが，候補の全部で学ぶ蒸留の組と K 本だけで学ぶ none に違う形で入る．計画の MOSEI の感度が無い
- 重さ：重大（計算の前に，判定の規則と集計の段の出力を直す）
- 箇所：
  - 設計 3.2 節の none（「K 本だけ」）と joint・joint_a1（候補の全部の発話に疑似ラベルを付けて学ぶ），4 節の H1・H1′．
  - 設計 3.3 節の「話者で中心化した版（副）」．判定の規則に入っておらず，区間も無い．
  - `DAI/CLAUDE.md` の評価の行「MOSEI は話者の代わりにチャンネルか動画で分けるので，同じ人物の別の動画が学習側に残りうる」．計画 8 節（重なり）「MOSEI は，チャンネルが分かる話者だけをテストにした集計を感度として出す」．`data/README.md` 3 節（3 モダリティの集合の発話の 68.5% が動画 ID の塊にある）．
- 問題：
  - MOSEI では，テストの動画に映る人物の別の動画が，動画 ID の塊として候補に入りうる．none はその候補のうち 4K 本（K = 25 でも 100 本）しか使わない．joint と joint_a1 は候補の全部（分割 0 で約 14,900 本）に教師の疑似ラベルを付けて学ぶ．
  - 人物 P の別の動画が候補にあると，声の生徒と顔の生徒は，P の声と P の顔のそれぞれについて，教師が P の動画に付けた確率に合わせて学ぶ．声の特徴にも顔の特徴にも人物の情報は入る．するとテストの P の発話では，2 つの生徒の点数が同じ向きにずれ，同じ感情の中の依存が動画の水準で増える．この増え方は「蒸留したから」だけでなく「蒸留で漏れた人物を覚えたから」でも出る（推測．人物の ID が無いので，漏れた人物の数は数えられない）．
  - DAI が土台にする Albanie ほか 2018 は，顔から声への蒸留で同じ近道を確かめるために，既知の話者と未知の話者で生徒の当たりを比べた（ROC AUC 0.71 と 0.69．`DAI_paper/参照論文/要点_問い1_別モダリティ蒸留.md` 3 節，https://arxiv.org/abs/1808.05561 ）．DAI-7 の設計には，これに当たる比べが無い．
  - MOSEI はテストが分割ごとに約 3,726 本，塊が 521〜524 個あり，区間が最も狭い．このため H1 を最も満たしやすく，「4 コーパスのうち 3 つ」に入る見込みが高い．
  - 話者で中心化した版は，MOSEI ではテストの塊（チャンネルか動画）ごとの平均を引くので，動画の水準のずれを除く．ただし判定に使わず，区間も無く，中心化で発話が外れる（gate-code の試走では MOSEI の分割 0 で 3,727 本のうち 792 本）ので，今の形では ΔD と比べられない．
  - 本検査が `DAI/splits/MOSEI.csv` と `data/metadata/mosei_channel_map.csv` で数えると，チャンネルが分かる塊のテストの発話は分割ごとに 30〜34% で，塊は 105〜127 個，感情ごとの本数は最少でも 40 本（分割 3 の Angry）である．15 本の規則に当たらず，感度は計算できる．
- DAI の基準との関係：データの扱いの欠陥（話者の漏れ）が，判定の向き（依存が増える向き）に偏って入りうる．計画が決めた MOSEI の感度も無い．このまま「MOSEI でも依存が増えた」と書くと，漏れによる分を蒸留の効果として報告するおそれがある．
- 直し方（どれも `fits/` の z・`test_cluster`・`test_group` から作れ，単位の段の計算は変えない）：
  1. MOSEI の感度：テストを，チャンネルが分かる塊の発話（`test_cluster` が `mosei_channel_map.csv` の `channel_id` に入る発話．`DAI/exp/dai3.py` の `subset_masks` と同じ定義）に限った ΔD（joint_a1 − none，joint − none，joint_a1 − oracle）を，同じ抜き直しをその塊に限って作った区間とともに `diffs.csv` に記述として出す．チャンネルが分かっても同じチャンネルの別の動画が候補に残りうるので漏れは 0 にならない，と添える（`data/README.md` 3 節）．
  2. 塊の水準の分：話者で中心化した D の差 ΔD_cent にも区間を付ける．比べられるように，中心化で外した発話を除いた同じ発話の上で，中心化しない ΔD も出す．
  3. 4 節に書き方の規則を足し，第 2 版の値を開く前に固定する．例：MOSEI で H1 を満たし，チャンネルが分かる発話の ΔD の点推定が全体の ΔD の半分未満か，その区間の下端が 0 以下なら，MOSEI の H1 の文に「同じ人物の別の動画が候補に残る漏れと分けられない」と添える．どのコーパスでも，同じ発話の上で ΔD_cent の点推定が ΔD の半分未満なら，「増えた依存の多くは話者（塊）の水準の共有である」と添える．「半分」の数は設計で決めてよい．
  4. 8 節に，MOSEI の話者の分離が不完全であることは，候補の全部で学ぶ joint・joint_a1 と K 本だけで学ぶ none に違う形で入る，と書く．
  5. 0 節の (e) に，出どころ（感情認識の査読者の A2）とともに書く．

## 軽微な指摘
- [a1] **IEMOCAP と MELD の区間の書き方**（重さ：軽微．直すと良い．統計の規則そのものは ML の査読者の範囲）：設計 4 節の 6「IEMOCAP は塊が 5 つ（分割ごとに 1 つ）なので区間は粗いと書く」は，区間が広く出るように読める．A1 の人工のデータの確かめのとおり，5 つの値の抜き直しの区間は t の区間より狭く出て，真の値を含む割合は約 84% である．MELD も，各分割のテストの 71〜82% を主役 1 人が占め，計画の数えで塊の実効の数が 8.6 なので，同じ向きがある．「粗い」を「塊の数が少ないので区間は狭く出る向きがある（5 つの値の抜き直しは t の区間の約 6 割の幅）」と直す．計画 8 節の IEMOCAP の規則（セッションの jackknife と自由度 3 の t）と並べるかは，ML の査読者の判断に任せる．
- [a2] **感情ごとの結果**（重さ：軽微．直すと良い）：`units.csv` には感情ごとの d_e と d_e⁰ の点推定があるが，`diffs.csv` に感情ごとの ΔD と区間が無く，`uar.csv` に感情ごとの再現率が無い．Albanie ほか 2018 は考察（5.3 節）で「顔と声に共通する感情の信号の量は感情ごとに違うかもしれない」と書き，Srinivasan ほか 2022 は音声と言葉の教師から音声の生徒への蒸留の得が感情価（快・不快の軸）に集中したと報告した（https://arxiv.org/abs/2112.00158 ．`DAI_paper/参照論文/要点_問い1_別モダリティ蒸留.md`）．査読者は「どの感情の中で依存が増えたか」を尋ねうる．`boot_D_unit` は感情ごとの値を平均の前に持つので，感情ごとの ΔD（joint_a1 − none，joint_a1 − oracle）とその区間，5 つのテストを合わせた件数を `diffs.csv` に足す．単独・prod・blk・full の感情ごとの再現率を `uar.csv` に足す．計画の A4 の規則に合わせ，1 回のテストの件数が 30 本未満のセル（AFEW の Neutral は分割によって 21 本，IEMOCAP の Angry は分割 3 で 22 本）は記述だけにする．感情ごとの主張の規則は置かない．
- [a3] **4 つのラベルの中身の違い**（重さ：軽微．8 節に書く．記述は任意）：同じ感情の中の依存には，4 つのラベルが拾わない感情の違いが入る．本検査の数えでは，IEMOCAP 即興の Happy 947 本のうち 663 本（70%）は元のラベルが excited で，分割ごとに excited 89〜174 本，happy 31〜106 本ある．MOSEI の Neutral 8,637 本のうち 62.2% は，どれかの感情の強さが 0 より大きく 0.5 未満である（Neutral は消去法で決まる．`data/README.md` 3 節）．MOSEI の Happy の強さは 10% 点 0.67 から 90% 点 2.0 まで広がる．教師がこの違いを持っていれば，2 つの生徒に写り，H1 の書き方では「教師の点数の揺れの写し」に数えられる．8 節に「同じ感情の中の依存には，excited と happy の違い，MOSEI の Neutral の中の弱い感情，感情の強さの違いが入る」と書く．記述を足すなら，IEMOCAP の Happy の中で元のラベル（`emotion_raw`）ごとの平均を引いた D と，MOSEI で 6 つの強さを感情の中で回帰して除いた D を出す（実験 3 の設計の D7 と同じ考え方）．
- [a4] **D の水準をコーパスの間で比べる文**（重さ：軽微．8 節に書く）：研究者の問いに「別のコーパスではモダリティの関連の仕方が違う」がある．D の水準のコーパスの間の違いには，ラベルの決め方（MOSEI の Neutral は消去法，IEMOCAP の Happy は excited を含む，AFEW はフォルダの名前，MELD は公式のラベル），産出の型（自然な発話は MOSEI だけ．計画の a3），テストの話者の作り（MELD は各分割の 71〜82% が主役 1 人，AFEW の分割 0 は 1 つの塊が 97.5%），AFEW の言葉が同じ音声からの機械の書き起こしであること（a5）が入る．8 節に「D の水準の違いを，コーパスごとのモダリティの関連の仕方の違いとは書かない」と書く．
