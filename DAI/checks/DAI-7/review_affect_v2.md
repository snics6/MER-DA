## 依頼された 4 つのグループの定義

- **筋書きで中心化した版**：上の A1 のとおり正しい．グループの（筋書き, 感情）は 1 つの分割のテスト（IEMOCAP では 1 つのセッション）の中で作るので，セッションを抜き直す区間の作りと矛盾しない．
- **MOSEI のチャンネルが分かる発話の版**：MOSEI の塊は，チャンネルが分かればチャンネル ID，分からなければ動画 ID である（`dai_data.clusters` の `speaker_group`）．YouTube のチャンネル ID（`UC` で始まる 24 文字）と動画 ID（11 文字）は書式が違うので，`np.isin` で動画 ID の塊が誤ってチャンネルに数えられることは無い．試走の MOSEI の分割 1 では 3,727 本のうち 1,233 本（33%）が印に入り，前回の数え（分割ごとに 30〜34%）と合う．
- **部分集合の版（`dai3.subset_masks` の印）**：
  - IEMOCAP の `marker` は「その発話の話し手がマーカーを付けていた側」である．発話一覧の `marker_side` と `utterance_speaker` で 2,943 本を照らすと，`marker` の 1,504 本はすべて両者が一致し，`nomarker` の 1,439 本はすべて一致しない．
  - AFEW の `asr_ok` は書き起こしの疑い 35 本（くり返し 30，「Thank you.」だけ 5）を除いた発話で，試走の分割 2 では 158 本のうち 151 本である．
  - MELD の `face_single` は顔が競らない（`single`）発話だけで，競る 5,234 本と決まらない 14 本を除く．試走の分割 0 では 2,105 本のうち 1,096 本である．
- **話者か塊で中心化した版**：
  - IEMOCAP の `speaker_id` は「セッション＋発話の話し手の性別」（例：Ses05_F）である．対話の名前の F・M（マーカーを付けた側）ではない．発話一覧の即興の全発話で，`speaker_id` と `session`・`utterance_speaker` から作った名前の食い違いは 0 本だった．試走の分割 0 ではグループが 2 つ（セッション 5 の 2 人）で，3 本の規則で外れる発話は 0 本だった．
  - MELD は別名をまとめ，複数の人の声を落とした後の話者，MOSEI はチャンネルか動画，AFEW は俳優と作品のつながりの塊で，どれもテストの塊そのものである．
  - 中心化は抜き直しの前にテスト全体で 1 回だけ行う．どのコーパスでもグループは抜き直しの塊の中に入れ子になっている（IEMOCAP の話者と筋書きはセッションの中，ほかのコーパスはグループ＝塊）．このため，塊を重複して引いても各グループの平均は 0 のままで，抜き直しは中心化を壊さない．
