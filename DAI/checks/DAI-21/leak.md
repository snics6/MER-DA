### 確かめた事実（指摘の前提）

- **CREMA-D の引き戻しの強さは CREMA-D を含まない**：`dai18_probe.stage_tether`（`dai18_probe.py:303-312`）は，T ごとに `d["T"] == T` の単位の K 本だけの分類器のテストの UAR で選ぶ．T ＝ CREMA-D の単位の仮のターゲットは AFEW・IEMOCAP・MOSEI・MELD・RAVDESS で，ソースは T と c を除いた残り（`dai18_probe.py:238`）なので，CREMA-D の発話もラベルも入らない．融合 AV の強さは同じ T の AVT の強さを写す（`dai18_probe.py:309-312`）．`tether.json` の CREMA-D の行は `AV|K` が `AVT|K` と同じ値で，`AV|K|own` は null（AV を持つ仮のターゲットが無い）である．
- **CREMA-D の提案の点は CREMA-D を含まない**：`select_points`（`dai18_probe.py:585-611`）は，c の点を `T == c` の単位で選ぶ．`sel.csv` の CREMA-D の 3 行は `n_units` 40，`pseudo_targets` が AFEW,IEMOCAP,MELD,MOSEI で，選んだ点は 3 つの K とも `M_F6_mix2`（n0 ＝ 0，β ＝ 1，eq）である．`stage_freeze` は単位の csv から選び直して保存の点と一致することと，単位の c とソースに CREMA-D が無いことを確かめて止める作り（`dai21_eval5.py:244-262`）で，試走の固定のファイルでは `corpora_in_units` が AFEW,IEMOCAP,MELD,MOSEI,RAVDESS だった．
