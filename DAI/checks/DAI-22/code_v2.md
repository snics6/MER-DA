### [I14b] 照合で止まった単位を，同じ置き場で流し直すと調べずに受け入れる
- 重さ：直してから進む
- 該当箇所：`exp/dai22.py:95-99`，`:185-186`，`:395-400`，`stage_summary`（`:289-298`）
- 問題：`run_unit` は照合の結果を待たずに npz と csv を書き（`:185-186`），`main` がその後で `bad` を見て `sys.exit` する（`:398-400`）．流し直すと `:97` の「同じコミットなら飛ばす」で `None` が返り，`:391-393` は照合を見ずに次へ進む．要約の段も `r0_saved_n_over_tol` と `r0_n_resolved` を `convergence.json` に書くだけで，両者が違っても止まらない．試走で，偽の「予測が 1 本違う」で止めた後に元の台本で流し直すと「済み（飛ばす）」と出て受け入れた（上の 7）．設計 6 節の「予測が 1 本でも違えば止める」は，1 回目の起動の中でしか成り立たない．第 1 版の報告の [I14] で書いた「再開すると調べずに受け入れられる」は直っていない．

### [R14] 解き直しが基準に届いたかを判定に使っていない
- 重さ：記録する
- 該当箇所：`exp/dai22.py:82-89`，`:153`
- 問題：`resolve_r0` は勾配の最大（`grad_tol<tol>`）を残すが，問ごとの止まり（`stalled_p`）と反復の数を残さず，`tol_resolved` は予測の違いの数だけで決まる．試走の MOSEI の行では 10⁻¹⁰ の解き直しが 2.86e-10 で終わり，基準に届かなかった（10⁻⁸ の解き直しは 9.98e-09 で届いた）．今回は予測の違いが 0 本なので判定は正しい．解き直しが出発点の近くで止まったまま「同じ予測」になる場合は理屈の上ではあり得るが，出発点からの判定と単位の解の判定が全候補で一致することは起こりにくい．
- 計算の後で直せるか：直せる（勾配の列は残る）
- 求める対応：`stalled_p` と `n_iter_p` も列に残し，`tol_resolved` の条件に「10⁻⁸ の解き直しの勾配の最大が 10⁻⁸ 以下」を足すことを勧める．足さないなら，結果の文で解き直した行の勾配の最大を書く．
