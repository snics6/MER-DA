## 指摘

### [C18] `kappa_from_dai14` が候補の全体の行だけに絞った後で部分集合の行を探すので，`summary` の段が止まる
- 重さ：直してから進む
- 該当箇所：`exp/dai23.py:266`，`:268-271`，`:325`（`kap = kappa_from_dai14()` を呼ぶ行．`stage_summary` の冒頭）；`exp/dai23.py:460-465`（selftest の (3)）
- 問題：`dai23.py:266` は第 2 版の絞り込み `x = p[(p.K == K) & (p.readout == "R1") & (p.control == "cl") & (p.subset == "all")]` を残したまま，`:269` で `y_ = x[(x["T"] == T) & (x.subset == sb)]` を作る．`sb` が `nomarker` か `nonshared` のとき `y_` は空になり，`:270` の `.iloc[0]` が IndexError を出す．`./.venv/bin/python` で `dai23.kappa_from_dai14()` を呼ぶと `IndexError single positional indexer is out-of-bounds` で止まった．`:266` の `& (p.subset == "all")` を外した同じ絞り込みでは，7 つの組すべてで P3 と P3b が 1 行ずつあり，比は `KAPPA_DESIGN` と小数 3 桁で一致した．このため設計 3 節の部分集合ごとの κ は正しく固定されているが，台本は `summary` の段（本番も退化の試しも）で止まり，前回求めた直しは出力に入らない．止まる向きの不備なので，誤った κ のまま判定が出ることは無い．selftest の (3)（`dai23.py:460-465`）は合成の数の式だけを確かめ，`kappa_from_dai14` を呼ばず，前回求めた「部分集合の κ なら帰無で M3 = 0，全体の κ では 0 にならない」の項も無いので，この誤りを selftest で見つけられない．
- 計算の後で直せるか：直せる（単位の計算は要らず，`summary` を流し直すだけ）．ただし退化の試しの集計もこの関数を通るので，本番の単位の前に直して退化の試しを通しておく．
- 求める対応：`dai23.py:266` の `& (p.subset == "all")` を外す．selftest に (a) `kappa_from_dai14()` を呼んで 7 つの組が返ること，(b) 合成の部分集合で D_s(A ← T)/D_s(A ← V) が全体の比と違うとき，部分集合の κ では帰無で M3 = 0，全体の κ では 0 にならないことの 2 項を足す．
