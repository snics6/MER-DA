## B．乱数の鍵の共有と，引き直し 1 回ごとの足し算（依頼の (c)）

- 鍵は集計の段と同じになっている．集計の段の差は `eff(As, Bs, c, ("A", a, b, c, K, sn))` から `seed_rng(*k_)`，つまり `P16.row_rng("dai20", "A", a, b, c, K, sn)` を使う（`dai20_eval.py:115-116, 418, 542`）．台本の `eff` は `P16.row_rng("dai20", "A", v, "prod", c, K, sn)` を使い，`v` は集計の段の名前である．入力も同じである．adj の `comb([v@adj])` は集計の段と同じ `_add`・`_finish` で作った数で，`sub()` の種の絞り方も同じである．A の通る場合で，MOSEI の区間の端が 3.6e-15 で一致したことがこれを裏づける．
- 引き直し 1 回ごとの足し算：`effect_stats` は分割ごとに `rng.multinomial` を 1 回だけ呼ぶ．呼ぶ前に乱数を使う処理は無く，塊の数は版と層によらない．このため，同じ鍵で作った「全体」「切片」「向き」は同じ重みの組で引き直される．`post_tools_run_v2/check_replicates.py` で，作り物の MOSEI（K=5・種 all，K=25・種 2-9）について，引き直し 2,000 回の値を `effect_stats`（173〜184 行）と同じ計算で並べた．「全体 − 切片 − 向き」の最大のずれは，鍵を共有したとき 1.4e-14（2 組とも）だった．前の版のように鍵を別にすると 2.5 と 4.4 になった．
- 鍵を共有しない量が 1 つ残る．水準の行（158 行）は `("dai20post", "L", …)` の鍵を使うので，MOSEI では水準の区間の端が集計の段の `levels.csv`（鍵 `("dai20", "L", c, K, v, sn)`）と少しずれうる．照合は水準の点推定だけを見る（記録 2）．
