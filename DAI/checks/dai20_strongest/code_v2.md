## SR_M_ext は「ソースのコーパスだけで決めた強さ」か

その意味で正しい．作りは `exp/dai16_probe.py` の `source_stats`（`SR_M_ext = M_ext`．`run_unit` の中で `arr["SR_ext"]` などと一緒に保存される）である．読んだ結果は次のとおり．

- `M_ext[m] = （ソース s で平均した）home_rel(s, m) × ret[m]`
  - `home_rel(s, m)`：ソース s の中の話者の 5 分割の交差検証で，ソース s だけで学んだモダリティ m の線形の分類器の d′（感情ごと．`dprime` は D_M_K と同じ関数）
  - `ret[m]`：ソースどうしの組 (s → t，s ≠ t，どちらもソース) について，s で学んだ分類器を t に当てた d′ の和を，s の中の d′ の和で割った「残り方」（0〜1.5 に切る）．モダリティごとに 1 つの数
- ターゲットのラベルも発話も使わない．`pairs` はソースの組だけから作る．流して確かめた結果，200 単位とも `srcs` にターゲットが入っていなかった
- ソースの組だけで決まるので，同じターゲットの 50 単位で値は同じである（流して確かめた結果，4 コーパスとも 50 単位で一致した．`top_ext` はコーパスごとに 1 通り）．つまり「ソースだけで決めた強さ」は，コーパスごとに 1 つの決まった予想になる．`agree_ext_rate` は「この 1 つの予想が単位ごとの正解と一致した割合」で，K 本の予想のように単位ごとに替わる予想と比べる形になる．結果の文でこの違いを書くこと（指摘 1）
- 分類器はソースで学んだ（学び直していない）分類器である．`D_M_orc` は学び直した ret の分類器の値なので，「ソースの分類器の強さから，ターゲットで学び直した分類器の強さの順位を当てる」比べになる．これは提案が水準の戻し先（`mix_rel` の `prior == "ext"`）として使う量と同じなので，提案の比べる相手としては合っている
- 平均の最大の同点は 200 単位で 0 だった．`tau_ext` に NaN は無かった
