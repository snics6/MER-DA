# 再現の手順（2026-11-15）

このフォルダ（以下「直下」）だけで論文の実験を流し直す手順である．パスはすべて直下からの相対パスで書く．
実験ごとの中身は `docs/実験の地図.md`，データの扱いは `data/README.md` が正本である．

## 1. 置き方

1. 直下を git のリポジトリの作業木にする（GitHub から取り出した形，または MER-DA の中の `DAI/`）．台本は起動のときに `git rev-parse HEAD` と `git status` を呼び，結果の記録にコミットと「作業木が汚れていたか」を書く．評価の段の多くは，作業木が汚れていると止まる．
2. Python の環境を直下の `.venv/` に作る．作り方は `requirements.txt` の冒頭（Python 3.12.3，torch 2.11.0＋cu126，残りは `pip install -r requirements.txt`）．起動の台本は `.venv/bin/python` を呼ぶ．
3. Python の外の道具：`git`，`bash` 5.1 以上，`ffmpeg`（特徴を作るときだけ），GPU（研究室の PC は RTX A5000 24 GB）．
4. 環境変数：`MERDA_GPU_FRACTION`（GPU のメモリの上限の割合．既定 0.6．`exp/dai_solver.py`）．
5. 直下に `logs/`（起動の台本が作る）と `results/` ができる．どちらも git の外である（`results/` の集計と記録だけは `results/MANIFEST.tsv` の一覧で git に入れる）．

MER-DA の研究室の PC では，`.venv`・`weights`・`logs` は MER-DA の直下のものへのリンク，`data/cache/*.npz` は MER-DA の `data/cache/` の 1 本ずつへのリンク，`results/` の下の実験の置き場は実体である（MER-DA の `results/` の同じ名前はこちらへのリンク）．

## 4. 守り（流し直すときに止まる条件）

- 評価の段（実験 1〜3）は `frozen/eval_gate.json` に並べた 40 本（設計，計画，固定のファイル，台本，査読と関門の報告）がコミット済みで sha256 が一致するときだけ動く．整理で置き場を変えたので，2026-11-15 に新しい置き場と sha256 で作り直した（`tools/remap_eval_gate.py`）．元の鍵と sha256 は `_meta.before_reorg`，中身が元と違うファイル（置き場の行を書き換えた台本 15 本と，評価の回の後に 1 行直した `docs/設計/実験1_設計.md`）は `_meta.changed_after_gate` にある．
- 実験 11〜13 の起動の台本は，出力の置き場が既にあると止まる．
- 実験 20・21 の台本は，前に流した単位の続きから流すとき，保存したコミットと今のコミットで見張りのファイルに差が無いことを確かめる．整理の前のコミットで作った単位の続きからは流せない．
- 固定のファイル（`frozen/dai*_frozen.json`）は書き換えていない．中にある説明の文のパスは整理の前の置き場のままである．

## 7. 分かっている限界

- 実験ごとに計算したコミットが違う（`provenance.json`）．整理の後の 1 つのコミットから全部を流し直した結果は無い．整理の後の台本が保存した値を再現することは，実験ごとに少数の単位で確かめた（`checks/整理_2026-11-15/`）．
- 実験 1〜3 の評価の回と実験 1 のソース・仮のターゲットの回は RunPod の H200 で，E77・E78 の一部は H100 で流した．GPU の種類が違うと値が小さくずれうる．
- 依存で入るライブラリ（`requirements.txt` に書いていない 63 本）の版は固定していない．
