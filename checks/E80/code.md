## A．本番の規模の見積もり

- **所要**：2 回目（poolC・mlp）の所要は学ぶ単位の数で増える（AVT の c ごとに，反復 1 つで 24〜30 秒，反復 2 つで 63〜83 秒）．反復 5 つで単位あたり 1 回目の時間は変わらず，2 回目は反復 1 つのときの 5〜7 倍と置くと，A5000（ほかの処理と共有）で AVT は約 35〜45 分，AV は約 2.5〜3.5 時間になる．AV は T 1 つあたり約 30〜40 分である．2 回目は 16〜20 個の小さな L-BFGS（float64）なので，H100 でどこまで短くなるかは読めない．H100 で最初の T 1 つの `parts/units_*.csv` の `sec_pass1` と `parts/pool_*.csv` の `sec` を見て，残りの見込みを出し直すこと

- **ディスク**：単位の npz は K 3 つで AVT の MOSEI 7.0 MB，MELD 4.3 MB，AV の 1 単位 0.3〜1.5 MB．AVT は約 0.15〜0.25 GB，AV は約 0.2〜0.3 GB で，合わせて 0.5 GB 以下である

## 指摘

### [I1・L4] `--summarize` が T をまたいで集計し，列名が E79 側の想定と違う
- 重さ：直してから進む（`--summarize` を流す前）
- 該当箇所：`exp/e80_teacher_j.py:401-403`
- 問題：`d.groupby(["world", "student", "teacher", "K"])` は評価のターゲット T をまたいで中央値を取る．gate-probe の [L1] は，T を評価するときの教師の集合に T のラベルが入るので T ごとに集計するよう求めている．列は `median_J, mean_J, n_units, frac_pos, keep` で，依頼で E79 が読むとされた `J_median` と違う．`exp/analyze_e79.py` はまだ `kept.csv` を読んでいない（grep で 0 件）．読んだだけ．
- 計算の後で直せるか：直せる．`j_units.csv` に `target` の列がある．
- 求める対応：`groupby` に `target` を足す（IEMOCAP 台本の T の扱いは指摘 6 の決め方に合わせる）．列名を 1 つに決め，E79 の読み込みを同じ名前で書く．`summarize` は単位の欠けを「注意」と表示するだけなので，欠けがあれば止めるようにする（I12）．

### [D1] agree の J は pF の J と恒等的に同じで，R3 は agree を pF と別に評価しない
