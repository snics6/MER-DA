## 指摘

### [S3・D] 判定 R2 の R は，単モダリティの最良をテストの半分の上で選ぶので，帰無でも正に偏る
- 重さ：直してから進む
- 該当箇所：`docs/exploratory-analyses.md:10143`，`docs/exploratory-analyses.md:10151`，`exp/analyze_source_pairs_e84.py:280`，`exp/analyze_source_pairs_e84.py:285`
- 問題：設計は「$R=\mathrm{mean}_{\text{対}}\max(0,\max_{\text{単}}a_B-a_B(\text{融合}))$」と定め，台本 280 行は `single_best = col.loc[list(singles)].idxmax()` で，評価する半分 B の値そのものから最良の単モダリティを選ぶ．285 行で `max(0.0, ...)` と 0 で切る．各 kind のソース s° は半分 A で選んでいる（交差している）が，モダリティの選択は交差していない．人工の計算（確認の計算 2）では，全 kind の真の a が等しくても R の期待値は AV で 0.62δ，AVT で 0.76δ になり，IEMOCAP のように seed が実質 1 つの単位では R ≥ δ が 10〜20% の確率で起きる．判定 R2 は「R が δ 以上の単位が過半」で余地ありと書くので，余地ありの側に偏る．実データでは同じ半分の話者を kind の間で共有するので雑音の相関があり，偏りの大きさはこの値と違いうる（推測）．偏りの向きは作りから正である．
- 計算の後で直せるか：直せる．`modality_cells_<世界>.csv` に半分ごとの a が残るので，交差した R を後から出せる．ただし判定の規則を値を見た後に変えることになるので，計算の前に設計を直す．
- 求める対応：R を交差で定義し直す．半分 A で「対ごとに最良の単モダリティ」を選び，半分 B でその単モダリティと融合の差を測り，入れ替えて平均する．対ごとの 0 での切り捨てはやめ，符号つきの差の平均を主にする（切り捨てた版は参考として並べる）．今の R は R_in と同じく内側の上限として扱う．

### [S6・S1] IEMOCAP の「seed 0〜4」は同じ話者の半分の繰り返しで，半分どうしが同じ対話を共有する
- 重さ：直してから進む
- 該当箇所：`docs/exploratory-analyses.md:10136`，`docs/exploratory-analyses.md:10150`，`exp/analyze_source_pairs_e84.py:97`，`exp/analyze_source_pairs_e84.py:234`，`measure/split.py:100`
- 問題：設計は「seed 0〜4」の平均を G とし，seed ごとに別の分け方になることを前提にしている．`speaker_folds` は大きい話者群から軽い袋へ入れる貪欲法で，seed は同数の群の順序にしか効かない（`measure/split.py:100`）．確認の計算 1 では，IEMOCAP-impro は 5 つの seed がすべて同じ分け方，IEMOCAP-script は 2 通りである．したがって IEMOCAP の単位の「seed の平均」はほぼ 1 回の分け方の値で，`gain_units.csv` と `modality_units_<世界>.csv` の G_min・G_max（台本 189〜190 行），R_min・R_max（289〜290 行）は IEMOCAP で幅 0 に近くなり，ばらつきが小さく見える．さらに IEMOCAP-impro の半分 0 は Ses03_F・Ses04_F・Ses05_F を含み，相手の Ses03_M・Ses04_M・Ses05_M は半分 1 に入る．同じ対話の 2 人が別の半分に入るので，半分 A と半分 B の a は対話を通じて相関する．このため，半分 A での選択が半分 B に持ち越され，G は独立な話者の上での選択の利得より大きく出うる．δ（半分どうしの差の中央値）は小さく出うる．
- 計算の後で直せるか：直せる（点数は保存済みで，分け方を変えて (A)〜(C) を流し直せば約 1 分）．ただし規則の前提を変えるので計算の前に直す．
- 求める対応：IEMOCAP はセッション（5 つ）を単位に分ける（例：2 セッションと 3 セッション，C(5,2) = 10 通りから 5 通り）か，seed ごとに話者を無作為に並べてから貪欲に入れる分け方にする．どちらにするかを設計 2 節に書き，実際の分け方の数（異なる分割の数）を出力に残す．MOSEI の話者は動画 ID の代用で，同じ人が両方の半分に入りうる（設計 10164 行に記載あり）．これも G を大きく，δ を小さくする向きであることを限界に書く．

### [S2] δ を全ターゲットで 1 つにまとめるので，発話の少ないコーパスほど R ≥ δ になりやすい
- 重さ：直してから進む
- 該当箇所：`docs/exploratory-analyses.md:10149`，`exp/analyze_source_pairs_e84.py:161`〜`166`，`exp/analyze_source_pairs_e84.py:273`〜`275`，`exp/analyze_source_pairs_e84.py:294`
- 問題：設計は δ を「kind ごとに，seed 0 の 2 つの半分で同じ (t, s, 対) の a を比べた差の絶対値の中央値」とし，台本は kind（世界では世界の全 kind）の全ターゲットをまとめて 1 つの中央値を取る．半分の中の 1 クラスの最少の発話数は RAVDESS 48，AFEW 79 と MELD 487，MOSEI 706 で 10 倍違い，a の雑音の標準偏差はおよそ √10 ≈ 3 倍違う（d の標準誤差を √(2/n) で近似した見積もり）．R は帰無でもそのターゲットの雑音に比例した正の値を取る（1 つ目の指摘）ので，まとめた δ を使うと AFEW のような小さいコーパスの単位が帰無でも「R ≥ δ」になりやすく，MELD・MOSEI の単位はなりにくい．判定 R2 は単位の数え上げなので，この偏りが判定に入る．G は帰無での期待値が 0 なので偏りは小さいが，「G ≥ δ」が何を意味するかが単位ごとに違う．

## 目録に無い種類の不備

- 案 S8：作りの上で正の値しか取らない量（最大値と 0 での切り捨て，選んだ同じデータでの差）を判定の基準と比べるときは，帰無（候補の間に差が無いとき）での期待値を計算の前に出すか，選ぶデータと測るデータを分けた（交差した）定義にする（E84 の関門 1．R が帰無でも δ の 6〜8 割を取った）．
- 案 S9：seed を変えて分け直す反復は，seed が実際に別の分け方を作るかを数える．`speaker_folds` は seed を同数の群の並べ方にしか使わないので，話者群の大きさがそろわないコーパス（IEMOCAP の 10 人）では seed を変えても同じ分け方になる（E84 の関門 1．IEMOCAP-impro は 5 つの seed で 1 通り）．
- 案 S10：「偶然の見込み」は，選ぶ手続きをそのまま帰無で回して出す（置換か人工の計算）．閉じた式（1 − 1/n など）を使うときは，比べる 2 つの選択が独立かを確かめる（E84 の関門 1．s* と s° は正に相関し，1 − 1/n が 0.16 大きかった）．
