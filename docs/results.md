# 結果：主張の現状と結果ファイルの場所（2026-10-08）

## 0. この文書の使い方

この文書は，MER-DA の結果を論文とスライドに使うときの入口であり，各主張の最新の状態（3 節）と結果ファイルの場所・作り方（4 節）を持つ．
論文（`~/papers/<論文名>/`）やスライド（`~/slides/decks/MER-DA/<用途>/`）は，別のチャットで `claude --add-dir ~/MER-DA` として作る．
結果そのもの（`results/`）は git の外にあるので，入口を git の中のこの文書に置く．

- **執筆側は MER-DA を読むだけで，書き換えない．**足りない結果や解析は，実験要求として MER-DA 側のチャットに返す（`~/papers/CCMER` と同じ分担）
- **進み具合**（何回終わったか，いま動いているか）は **`results/status.md`**（機械が読むなら `results/status.json`）にある．`./.venv/bin/python exp/results_status.py` で作り直す．この表は UAR などの値を含まない
- **数値は結果ファイルから取り，出典を添える．**3 節の数値はすべて保存した CSV から取り直した（md からは写していない）．出典は 5 節にある
- MER-DA 側では，新しい結果が出たら `docs/exploratory-analyses.md` に記録し，同じ日にこの文書の 3 節と 4 節も直す

## 2. 結果を使うときの決まり

- **数値は結果ファイルから取り，出典（ファイル・列・条件）を添える．**集計は 4 節の台本の出力から引く．執筆側で新しい値を計算しない
- **最新の値はこの文書の 3 節から取る．**`docs/exploratory-analyses.md` に残る古い反復回数の値を写さない
- **状態が `complete` でない結果（`partial`，`quick (R=1)`）は，論文の主張の数値に使わない．**速報（反復 1 回）は傾向を見るためだけに使う
- **K* は反復が 30 回そろうまで暫定である**（`kstar.csv` の `status` 列が `provisional`．言葉を含む 4 種類は 5 回なので暫定）．**IEMOCAP がターゲットの組は，K* の区間の計算法が未決である**（`status` 列が `iemocap_interval_undecided`．`docs/researchvision.md` の『未決事項』）
- **オラクルの列（`uar_oracle`，`C_oracle`，`test_uar_C*`）は分析専用である．**手法の性能として報告しない（`CLAUDE.md`）
- **事前登録した判定は，`docs/researchvision.md` の『事前登録した仮説と判定』に登録した手順でだけ行う．**H1〜H6 と P1〜P4 はまだ判定しておらず，H7 と MH の HuBERT での確認は判定済みである（3.5 節）
- **E シリーズは，結果を見た後に方法を決めた探索的な結果である．**登録した判定と区別して書く（3.1 節の「確かめ方」）

### 3.4 解析の仕分け（2026-10-08 決定）
