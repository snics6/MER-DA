# 特徴の作り方（2026-09-20 合意）

前身のキャッシュは引き継がず，**生データから作り直す．**設計は次の 4 点を前身から変える．

1. **顔検出の結果（フレーム番号と矩形座標）を保存する．**後で別の表情モデルに
   差し替えても，完全に同じ切り出しを再現できる．「エンコーダ 1 種では交絡する」
   という査読指摘への唯一の対処であり，**作り直す最大の理由**
2. **セグメント数 `n_segments` を記録する．**短い発話の判定を間接的にしない
3. **平均と標準偏差を分けて保存し，既定は平均のみ．**3 モダリティで時間の扱いを揃える．
   前身では映像の標準偏差 512 次元が「発話の短さ」を運んでいた
   （40,037 件中 15,292 件＝38.2% が丸ごと 0．割合は AFEW 89.8%〜MOSEI 17.7% で 5 倍違う）
4. **RAVDESS・CREMA-D も映像込みで取る．**前身では音声しか無く，5 コーパスの実験が
   音声限定になっていた

素のエンコーダの内訳：映像 ResNet-50（AffectNet 事前学習）／音声 `microsoft/wavlm-large`／
言葉 `roberta-base`．第 2 エンコーダは音声 `facebook/hubert-large-ll60k`／
言葉 `microsoft/deberta-v3-base`．

## 実装

### 特徴

| モダリティ | | コード | 出力（`data/cache/`） |
|---|---|---|---|
| 映像 | 第 1 | `features/build_video.py` | `video_<corpus>.npz`・`faces_<corpus>.csv.gz` |
| 映像 | 第 2 | `features/build_video_clip.py` | `video_clip_<corpus>.npz` |
| 音声 | 第 1 | `features/build_audio.py` | `audio_wavlm_<corpus>.npz` |
| 音声 | 第 2 | 同上 `--model facebook/hubert-large-ll60k` | `audio_hubert_<corpus>.npz` |
| 言葉 | 第 1 | `features/build_text.py` | `text_roberta_<corpus>.npz` |
| 言葉 | 第 2 | 同上 `--model microsoft/deberta-v3-base` | `text_deberta_<corpus>.npz` |

第 2 エンコーダは**別のコードではなく `--model` の切り替え**である（映像を除く）。
使えるモデルは `features/common.py` の `AUDIO_MODELS`・`TEXT_MODELS` に限られ，
綴り違いは実行前に弾かれる。出力名が短い名前で分かれるので**第 1 と第 2 が混ざらない**。

映像だけ別コードなのは，第 1 が保存した顔の矩形（`faces_<corpus>.csv.gz`）を読み直して
**まったく同じ画素**を CLIP に渡すためである。

### 言葉の正規化の段階

`build_text.py --level N` で **L0〜L4** を切り替える。
既定は **L1**（文字化けの修復のみ）。出力名に `_L2` のように段階が付くので混ざらない。

| 段階 | やること |
|---|---|
| L0 | 何もしない |
| **L1** | 文字化けの修復のみ（**既定**） |
| L2 | L1 ＋ 引用符・ダッシュ・省略記号を ASCII に |
| L3 | L2 ＋ `[LAUGHTER]` のような注記を削除 |
| L4 | L3 ＋ 文末に句点を補う |

**感嘆符と疑問符は L4 でも消さない。**感情の手がかりそのものだから。

各コードの先頭に，前身から変えた点とその根拠を書いてある．**実装を変えたら
この文書と両方を直す．**

## 数値の約束

| 項目 | 値 | 理由 |
|---|---|---|
| 音声の長さ上限 | **60 秒** | 20 秒だと切られる 464 件のうち 435 件が MOSEI で，処理がコーパスに偏る．60 秒なら 9 件（0.02%）．MELD に 305 秒の異常値があるので上限自体は必要 |
| 計算の精度 | **fp32** | fp16 は音声の特徴が平均 1.9% ずれる（値の平均 0.0480 に対し平均差 0.00090）．速度の利得は無い |
| 顔検出のしきい値 | 0.25 | 前身は 0.01 で誤検出していた．検出した顔は**すべて座標を保存**するので後から変えられる |
| フレームの間引き | `int(fps × 5 / 25)` | 前身と同じ（30fps なら 5 枚に 1 枚） |
| セグメント | window 4・step 2・need_frames 5 | 前身と同じ |

## 言葉の前処理（2026-09-20 追加）

### 文字化けの修復（既定で行う）

**MELD の転写の 28.1%（11,352 件中 3,191 件（**4 クラスに入る 11,353 行が母数**．全 13,708 行なら 3,741 件＝27.3%））に Windows-1252 の文字が壊れて混入している。**
IEMOCAP と MOSEI は 0 件である。

| 壊れた文字 | 延べ回数 | 本来 |
|---|---:|---|
| `\x92` | 4,192 | ’ 右引用符（`don't` の `'`） |
| `\x85` | 157 | … 三点リーダ |
| `\x97` | 134 | — 長ダッシュ |
| `\x91` | 101 | ‘ 左引用符 |
| `\x93` `\x94` `\x96` | 14 | “ ” – |

**直さないと何が起きるか。**RoBERTa は byte 単位の BPE なので処理自体はできるが，
`company\x92s` が `Ġcompany / Â / Ĵ / s` という**MELD にしか現れないトークン列**になる
（修復後は `Ġcompany / âĢ / Ļ / s` で MOSEI と同じ）。DeBERTa-v3 ではさらに深刻で，
**fast と slow のトークナイザで結果が食い違う**（MELD 3,000 件中 847 件＝28.2%）。

実装は `common.fix_mojibake`。直した件数は npz の `n_mojibake_fixed` に記録する。

### 記号の正規化（既定では行わない）

3 コーパスで表記の規則が違う（文字の延べ数）。

| コーパス | ASCII `'` | 壊れた `\x92` | 正しい `’` | `“ ”` | `— –` | `…` |
|---|---:|---:|---:|---:|---:|---:|
| IEMOCAP | 7,404 | 0 | 0 | 0 | 0 | 0 |
| MOSEI | 10,150 | 0 | 1,179 | 260 | 153 | 17 |
| MELD | 2,397 | 4,192 | 64 | 0 | 0 | 5 |

**文字化けを直しても，IEMOCAP（ASCII のみ）と MOSEI・MELD（Unicode の記号を使う）の
差は残る。**この差が「コーパスの違い」として検出されると，感情表現の違いと交絡する。

`build_text.py --normalize-punct` で ASCII に揃えた版も作れる（`text_<model>_norm_*.npz`）。
**既定では使わない。**言葉でのコーパス当ての測定結果を見てから，揃えた版と比べて決める。
