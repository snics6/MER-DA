## 指摘

### [C4] 手の比較が「仮説転移が最も高い」を判定するのに，線形の教師ありの DA の標準の比較相手 AUGMENT と WEIGHTED が手に無い
- 重さ：直してから進む
- 該当箇所：`docs/exploratory-analyses.md:7930-7936`（手 h2〜h8 の表），`docs/exploratory-analyses.md:8033-8040`（2.4.5 節の判定「K=5・10 で，仮説転移（h7）と次に高い手の差の区間が 0 より上 → 『仮説転移が最も高い』を残す」），`exp/relearn_e76.py:68`（`HANDS_ALL = (2, 3, 4, 5, 6, 7, 8)`），`exp/relearn_e76.py:476-493`
- 問題：手の比較が支える主張は，ソースのラベル付きデータとターゲットのクラスあたり K 本を使う教師ありの DA（ラベル無しのターゲットを使う手を含めれば半教師ありの DA）で，学習器は凍結した特徴の上の線形の分類器である．この種類の標準の比較相手は Daumé 2007（"Frustratingly Easy Domain Adaptation"）の SRCONLY・TGTONLY・ALL・WEIGHTED・PRED・LININT・PRIOR と，同論文の AUGMENT（特徴を共通・ソース専用・ターゲット専用の 3 つに複製する）である．`docs/related-work.md` 1.8.2 節は「Daumé 2007 が [Chelba & Acero の MAP 適応を] PRIOR として比較に含めた」「提案の AUGMENT の次点とした」と書き，1.7 節は Finkel & Manning 2009 が AUGMENT の一般化で合併と Daumé 07 を上回ったと書く．E76 の手は SRCONLY（②），TGTONLY（①），ALL（③），PRIOR（h7）を含むが，AUGMENT と WEIGHTED を含まない．h6（ターゲット専用の切片つき合併）は AUGMENT のうち切片の列だけを足した版である．原論文で PRIOR は AUGMENT に次ぐ 2 位だったので，査読者は「AUGMENT と比べずに仮説転移（PRIOR と同じ形）が最も高いとは言えない」と指摘できる．WEIGHTED は E31 の O1（重みつき合併）として別の計算にあるが，E76 の手の表とは反復も区間の作り方も違い，2.4.5 節の「次に高い手」の候補に入らない．
- 計算の後で直せるか：直せる．テストの袋と K 本は反復番号から決まる（`map.test_mask`・`map.kshot_order`）ので，同じ分割で手を足して後から計算できる．ただし GPU の計算を足すことになり，`docs/methods.md` 9.3 節 R6 は標準の比較相手を最初の計算に入れることを求める
- 求める対応：次の 2 つの手を `run_hands` に足してから流す．(i) AUGMENT：ソースの行を [x, x, 0]，ターゲットの行を [x, 0, x] にして合併し，C ＝ ② の C で `logreg.fit_batch` で解く（K=1・5・10．テストは [x, 0, x] で点数を出す）．(ii) WEIGHTED：E31 の O1 と同じ定義（ターゲットの重みの和 α S，ソースの重みの和 (1 − α) S）で，α の格子の全候補の点数を残し，α は仮のターゲットで選ぶ（E31 と同じ規則）．融合の種類で次元が 3 倍になって計算量が見積もりを超えるなら，単モダリティの種類（A・V・T・A(HuBERT)）だけに足し，2.4.5 節の判定の文を「融合の種類では AUGMENT・WEIGHTED と比べていない」と限る．足さない場合は，2.4.5 節の判定の文を「8 つの手の中で仮説転移が最も高い」に替え，AUGMENT と WEIGHTED を比べていないことと理由を設計の 5 節（範囲の外）に書く

### [C1] ラベル無しのターゲットとして使う発話の範囲が手ごとに違い，テストの発話を含む手がある
- 重さ：記録する
- 該当箇所：`exp/relearn_e76.py:280-282`（`mean_t = tgt.X.mean(0)`．ターゲットの全発話），`exp/relearn_e76.py:491`（`IV.coral(Xs, tgt.X)`），`docs/exploratory-analyses.md:7938`（「ターゲットの全発話（テストを含む．ラベルは使わない）の平均」），`docs/exploratory-analyses.md:8117`
- 問題：h2・h3・h5・h8 はテストの発話の特徴（ラベル無し）を使う変換的な（transductive）設定で，h7・h4・h6・③ は使わない．2.4.5 節の判定では h7 に不利な向きなので，「仮説転移が最も高い」を水増ししない．しかし次の 2 点で読み手が比較を取り違える．(a) 2.4.4 節と説明資料 p2 の「中心化（ラベル無し）だけで上がる」は，テストの発話の平均を使った値である．(b) E78 の CORAL ＋ none は候補（テストを含まない）の共分散を使う（`docs/exploratory-analyses.md` の E78 の節「ソースと候補を合わせた特徴」）．E76 の h8 と E78 の CORAL は受け取るラベル無しのデータが違うので，論文で同じ「CORAL」の行として並べると情報のそろわない比較になる．
- 計算の後で直せるか：記述は直せる．候補だけの平均で中心合わせした版は学び直しが要る（h2 は全発話の点数と係数を残すが，中心は学習の前に引くので後から替えられない）
- 求める対応：手の表（2.4.5 節の表と論文の表）に「ラベル無しのターゲット：テストを含む全発話／使わない」の列を足す．h8 と E78 の CORAL を同じ行や同じ判定に並べないこと，並べるなら情報の違いを書くことを 2.4.5 節に書く

### [C5] ターゲットのみの C の規則の感度が ① の側だけにあり，③ の C の規則は動かさない
- 重さ：記録する
- 該当箇所：`docs/exploratory-analyses.md:7993`（2.4.3 節の規則．仮のターゲットの規則は ① の C だけを選ぶ），`docs/exploratory-analyses.md:8108`（合併を C 4 つで解くことは範囲の外），`exp/relearn_e76.py:339`（`Cm = C_GRID if merged_all_c else (C,)`．既定は ② の C だけ）
- 問題：2.4.3 節は「K=1 の利得はターゲットのみの C の規則に依らない」を判定する．別の規則では ① だけが仮のターゲット（ほかの評価のターゲットのテストの UAR）で C を選び直し，③ はソースの交差検証の C のままである．利得 ③ − ① の両側で選び方がそろわない．① を強める向きなので，利得が正という主張を水増しはしないが，「利得は C の規則に依らない」と書くと，③ の C の規則を動かしたときの依存が測られていないことが読み手に伝わらない．`--merged-all-c` を付けないので，③ を別の C で評価する点数は残らない（R4）．
- 計算の後で直せるか：記述は直せる．③ の C の規則の感度は，③ を学び直さないと出せない
- 求める対応：2.4.3 節の判定の文を「K=1 の利得はターゲットのみの C の規則に依らない（合併の C はソースのみの C に固定したまま）」とし，③ の C の規則を動かした感度を出さない理由を 5 節に書く（いまの 8108 行の理由は交差検証の地図の話だけである）．計算量が許すなら K=1・5 に限って `--merged-all-c` を付けることを検討する

## 目録に無い種類の不備

- **C9 案（主張の文と計算する版の照合）**：主張の文（説明資料，論文の下書き）が名指す手法の版（中心合わせの有無，出発点，罰則の中心，切片の扱い）と，設計の判定が評価する版が同じかを照合する．違えば，文を計算する版に合わせるか，名指す版を計算に入れる（E76 の検査．説明資料 p3 の「中心化してからの仮説転移」と h7）
