### [S3] 1．族の複製を jackknife の幅まで広げる処理が，包絡では限りの点を中心にするので，L が下限・U が上限でなくなる
- 重さ：直してから進む
- 該当箇所：`exp/analyze_value_split_e87.py:972`（`pkey, bkey = {None: ("point", "B"), "L": ("pt_lo", "LB"), "U": ("pt_up", "UB")}[env]`），`:986`（`b, x = cd[c][bkey], cd[c][pkey]`），`:994`（`reps.append(np.where(np.abs(b) >= BIG / 2, b, x + r * (b - x)))`）；設計 `docs/exploratory-analyses.md:10671`（「G_eff < 20 のコーパスの複製を点の値のまわりで jackknife の t 区間の半幅まで広げ」），`:10672`（包絡）
- 問題：包絡の複製は x ＋ r·(b − x) で広げるが，x は記録した点ではなく点の限り（`pt_lo` か `pt_up`）である．(i) 点が上に打ち切られた読めないコーパスでは x ＝ ±10⁶ 前後になり，抽出が打ち切られていない複製（b が有限）は L で b ＋ (r − 1)(b ＋ 10⁶)，つまり ＋10⁶ の桁に飛ぶ．U では逆に −10⁶ の桁に飛ぶ．どちらも判定に有利な側である．`t5.py` の T4 で，none が上に打ち切られた G_eff ＝ 8 のコーパス（抽出の 40% が打ち切り）の L の複製の 60% が ＋2.04×10⁶ になった．(ii) 点があいまいで `pt_lo` が点より小さいときも，x ＋ r·(b − x) と点を中心にした値の差は (r − 1)(点 − pt_lo) だけ上に出る（`t5b.py` の例 B：抽出の 100% で L が記録した値より上，中央値で 18.66 本上）．(iii) 判定が変わる例（`t5b.py` の例 A）：読める 4 コーパスと，none が上に打ち切られた MOSEI（G_eff ＝ 8，抽出の 10% が打ち切り）の族で，台本の L の包絡の lo[med_L] は 0.094 で P87-1 の前半の確かめ（lo[med_dir(0)_L] > 0）を通る．同じ倍率で記録した点を中心に広げると −0.146 で通らない（記録した値の全コーパスの族の lo も −0.146）．抽出の 90% で L が記録した値より上にあり，L は下限になっていない．広げない版（感度 (l)）は −0.148 で通らない．影響は G_eff < 20 で倍率が 1 を超えるコーパスが読めないか，点に下・上・あいまいの印があるときに出る．主の設定（`jk_inflation` ＝ True）の最終の区分のすべて（P87-1〜3，(A)(C)，教師に帰す規則）に入る．
- 計算の後で直せるか：直せる（`boot_units.npz` の単位の `|lo`・`|up` と `corpus.csv` の点と jackknife の区間から族の包絡を作り直せる）．ただし最終の区分の規則を計算の後に直すことになり，`judgments.csv` を作り直すので，計算の前に直す方がよい
- 求める対応：倍率 r で広げる中心を，記録した値の版と L・U の版で同じ点（`cd[c]["point"]`）にする（`x = cd[c]["point"]` を 3 つの版で使う）．x ＋ r·(b − x) は b について増える関数なので，抽出ごとの L ≤ B ≤ U の順序が保たれる．±10⁶ の複製を広げない `np.abs(b) >= BIG / 2` の条件は残してよい（記録した値の複製は全件の本数より小さい有限の値なので，限りの複製が ±5×10⁵ 前後で条件の境をまたいでも，x ＋ r·(b − x) は同じ側に大きくなり L ≤ B ≤ U は崩れない）．人工の族で「L の複製が記録した値の複製を抽出ごとに上回らない」ことを確かめる検算を試走に足す．

### [S3] 2．あいまいの読みの上限は，最後の読みも右端を越えるときに 10⁶ でなく K_all に置かれる
- 重さ：直してから進む
- 該当箇所：`exp/analyze_value_split_e87.py:568-569`（`Kn_l = read_K(curve, logk, v_n, better_high, adjust="last")[0]`．最後の読みの打ち切りの印を捨てる），`:559`（`up_b = np.where(am, np.maximum(Kf, Kl), Kf)`），`:204`（届かなければ `logk[..., -1]` に置く）；設計 `docs/exploratory-analyses.md:10661`（「あいまい → 最初の読み（累積の最大で整えた曲線）と最後の読み（右からの累積の最小で整えた曲線で読む）の間」）
- 問題：右からの累積の最小で整えた曲線の右端は，整える前の曲線の右端（K ＝ 全件の値）と同じである．値 v が全件の値より良く，それより左のどこかの点より悪いとき（右端で曲線が下がっている場合），最初の読みは有限で，最後の読みでは v が曲線の右端を越える．つまり最後の読みの意味では上の打ち切りで，本当の本数の上限は無い．台本は最後の読みの打ち切りの印を捨て，K_all を上限にする．`t5.py` の T5 で，曲線 [60, 70, 74, 80, 84, 86, 83]（K ＝ 1〜全件，全件を 400 本に置いた）に v ＝ 84.5 を当てると，最初の読みは 59.5 本，最後の読みは「打ち切り」の印つきで 400，限りは [59.5, 400] になった．本当は [59.5, 10⁶] である．none の読みでこれが起きると n の下限 lo(m) − up(n) が高く出て L の包絡が判定に有利な側にずれ，手法の読みで起きると U の包絡が低く出る．右端の手前で曲線が下がる場合は，位置の座標（S_pos）や K ＝ 100 と全件の間で起こりうる（整えた点の数は仮定 1 で数えるが，この場合の数は残らない）．
  あわせて記録：あいまいの印が無い読み（整える前の曲線が v を 1 回だけ横切る）でも，補間の区間の左端が整えた点なら最初の読みと最後の読みが違う．`t5c.py` で曲線 [60, 66, 70, 65, 75, 80, 85]・v ＝ 72 は最初の読み 33.0 本，最後の読み 40.6 本で，あいまいの印は付かず，限りは [33.0, 33.0] になった．これは打ち切りではなく補間の不確かさで，感度 (c)（整えない読み）が扱う範囲だが，「読みごとに本当の本数の下限と上限を持たせる」という設計の文とは合わない．
- 計算の後で直せるか：直せない（最後の読みの打ち切りの印も，抽出ごとの最後の読みも保存しないので，限りを作り直すには計算をやり直す）
- 求める対応：`read_bounds` で最後の読みの上の打ち切りの印も受け取り，`bounds_of` で「あいまいかつ最後の読みが上の打ち切り」の上限を `BIG` にする．あいまいの印の無い読みも限りを [最初の読み, max(最初の読み, 最後の読み)] にするかは設計者が選び，選んだ方を設計 2.3 節に書く（どちらにしても計算の前に決める）．T5 の 4 つの曲線を試走の検算に足す．
