### [I1] 1．あいまいの読みで，最後の読みが上に打ち切られるとき，本当の本数の上限を 10⁶ でなく K_all に置く
- 重さ：止める
- 該当箇所：`exp/analyze_value_split_e87.py:559–560`，`:568–569`
  ```

  ...

  ```
- 問題：`read_K(..., adjust="last")` は，右からの累積の最小で整えた曲線がどこでも値に届かない（曲線の右端が値より悪い）とき，読みを K_all に置き，上の打ち切りの印を返す．`read_bounds` は印を捨て（`[0]`），`bounds_of` は上限を max(最初の読み, K_all) ＝ K_all にする．コミットした設計 2.3 節は「上の打ち切り → K' ≥ K_all（上限は 10⁶ 本に置く）」とし，あいまいの上限は最後の読みなので，最後の読みが上に打ち切られれば上限は 10⁶ である（作業中の設計は「最初か最後の読みが上に打ち切られていれば 10⁶」と明記した）．流して確かめた：人工の曲線（1, 5, 10, 25, 50, 100, 400 本で 10, 30, 20, 40, 50, 55, 22．値 25）で，最後の読みの上の打ち切りの印は真，上限は 400 だった．試走では，あいまいの読み（点 870，抽出 31,818）のうち点 818，抽出 24,732 がこの場合だった．手法のあいまいでは U の包絡が，none のあいまいでは L の包絡が不利な側の限りより内側に出るので，最終の区分が `undet_censoring` になるべき行で当たり・外れ・負になりうる

### [I1] 2．包絡（L・U）の複製を，限りの点のまわりで jackknife の幅まで広げるので，抽出ごとの L ≤ 記録 ≤ U が崩れる
- 重さ：止める
- 該当箇所：`exp/analyze_value_split_e87.py:986–994`
