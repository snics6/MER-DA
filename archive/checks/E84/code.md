### 指摘 1．[R4・R7・L4] 学び直しが要る 3 つの求めが，設計の 5 節で範囲の外と書かれていない
- 重さ：止める
- 該当箇所：`docs/exploratory-analyses.md` E84 5 節．台本 `exp/analyze_source_pairs_e84.py:85-87`（入力は 1 つの C の点数だけ），`:34-35`（世界は第 1 エンコーダだけ）
- 問題：次の 3 つは保存した点数からは出せず，計算の後に求められると GPU で学び直すことになる．(1) ソースのみの分類器の C を変えたときに s\* と G が変わるか．`results/shift_<kind>/logits` は交差検証で選んだ 1 つの C の点数だけで，地図の `test_uar_C<C>` には UAR しか無い．(2) 1 節が引く研究者の問いは「このソースのこのサンプル」だが，E84 はソースとモダリティの単位までで，shift の分類器の W・b もソースの発話ごとの寄与も保存されていない．(3) (C) の第 2 エンコーダの世界．`results/shift_fuse2-*` の点数は無い（gate-code が `ls -d results/shift_*/logits` で確かめた）．5 節は「E39 の分類器ではない」「全部混ぜる分類器は保存されていない」を書くが，この 3 つは書いていない（読んだだけ）
- 計算の後で直せるか：直せない（3 つとも学び直しが要る）
- 求める対応：5 節に 3 行を足し，主張をその範囲に限る．(1)「ソースのみの分類器の C は交差検証で選んだ 1 つだけ（地図の src_only と同じ）で，C を変えた感度は測らない」．(2)「サンプル単位の選択は扱わない．発話単位の選択は E55・E56 で全部使うに勝てなかった」．(3)「(C) は第 1 エンコーダだけ．HuBERT は (A)(B) の音声で確かめる」．どれかを計算に入れるなら，その学び直しを先に設計に書いて関門を通す
