## A．小さく流した結果
- コマンド：`./.venv/bin/python -W default exp/analyze_projection_e85.py --smoke --out checks/E85/code_run/smoke`．壁時計 68 秒，CPU のメモリの最大 1.98 GB．avt・T = IEMOCAP-impro・c = MELD と MOSEI・反復 0・λ = 1e-3 の 2 ファイル．出力は units 48 行，pairs 288 行，per_unit 48 行，summary 24 行．検査の後に消した
- 警告：237 行の `DataFrame.max(1)` に Pandas4Warning（pandas 4 で引数をキーワードにしないと落ちる）．収束の警告は出ない（L-BFGS は警告を出さない）
- NaN・Inf：Inf は 0．NaN は作りの上で空になる列だけだった．units の `*_cand` の 5 列（K = 5・25 と λ = 0.1 の行），pairs の `a_g`（g = ref の行），per_unit の `J_cand`・`r_rep_cand`（K > 0），summary の `J_cand_median`・`r_rep_cand_median`（K > 0）．同じ識別子の重複は units・pairs とも 0．`uar_method_*` に NaN は無い
- 本番で予定する行の数：units 2,160（avt 24 × 30，av 72 × 20），pairs 12,960，per_unit 152（avt 3 f × 8 (K, g) × 3 単位，av 2 × 8 × 5），summary 40
- 保存済みの値の再現：E77 の none の行と `none_te` の UAR は，反復 0〜2 の 96 ファイル × (単 f と融合) × 3 K で差の最大 7.1e-15．teacher の pF・pFK の行も同じく 7.1e-15．E77 の `<T>_ps_<c>_r<r>_none.npz` の `te` は E80 の `te` と同じ（1 ファイルで確かめた）
- 退化した場合の検算（`check_self.py`）：q を f 自身の出発点の確率 P__f（f の特徴の線形 softmax）にすると，proj は出発点を再現するはずである．float64 で解き，λ = 1e-5 では損失 − H(q) が 0.0000，テストの argmax の一致は 0.981〜1.000（5 組．AFEW の音声が 0.981）．λ = 1e-3 では一致 0.962〜1.000，UAR の差 −1.96〜+0.12 ポイント（−1.96 は AFEW の音声．候補 636 本に次元 1024）．λ = 1e-1 では一致 0.848〜0.975，UAR の差 −1.45〜+2.10．つまり主の λ = 1e-3 でも，完全に表せる q に対して proj の UAR は最大 2 ポイントずれる
- 束ねた当てはめと 1 問ずつの当てはめ（`check_fit.py`）：目的関数は問ごとに足し合わせた形で，問の間で母数を共有しない．したがって最適解は問ごとに解いた解と同じである（勾配はブロックごとに分かれ，ヘッセ行列はブロック対角）．ただし L-BFGS の止める判定（反復の上限，tolerance_change，tolerance_grad）は束全体で 1 つなので，途中で止めた解は束ね方に依る．実測：
  - avt・T = IEMOCAP-impro・c = MELD・r0・音声（9 問を束ね，370 回で停止）：束ねた解の損失は float64 で収束させた解より 8e-6〜1.2e-5 大きい．テストの UAR の差は最大 0.13 ポイント，argmax の不一致は 2,115 本中 2〜10 本
  - av・T = AFEW・c = CREMA-D・r1・音声（9 問を束ね，**上限の 400 回で停止**）：損失の差 1.7e-4〜3.1e-4（1 問ずつの float32 なら 1e-5 以下）．UAR の差は最大 0.61 ポイント（ref，K = 5），pFK の K = 5 で 0.53．argmax の不一致は約 970 本中 4〜10 本．同じ単位の映像（312 回で停止）では UAR の差は最大 0.33
  - 本体の `fit_soft` と，罰則の和を問ごとに取る順に変えただけの写しとで，同じ入力の UAR が最大 0.41 ポイント違った（CREMA-D の音声，pFK，K = 5）．丸めの違いで結果が動く
- 反復の数（`check_iters.py`，本体の `run_unit` を λ 2 つで流し L-BFGS を包んで数えた）：5 ファイルの 48 回の当てはめのうち 9 回が上限 400 回に達した．終わりの勾配の最大絶対値は単位ファイルごとの最大で 1.8e-4〜5.4e-4 であり，tolerance_grad 1e-5 を上回る．`check_fit.py` の 18 問でも，束ねた解の問ごとの勾配は 8e-5〜7e-4 ですべて 1e-5 を上回った．どの当てはめも勾配の基準では止まっていない

## A．本番の規模の見積もり
- 今の台本（λ 2 つ，反復 0〜2）：1 ファイルの `run_unit` は avt で 21〜33 秒，av で 15〜26 秒（実測 7 ファイル）．96 ファイルで約 40 分．設計の見込み（1 ファイル約 1 分，96 分）より短い
- GPU のメモリの最大は 96 MiB（MOSEI の候補 14,907 本）．6 割の制限と空きブロックを返す処理は無いが，この大きさでは要らない．計測の時点で GPU を使う他の計算は無かった（`nvidia-smi` で 1.4 GiB の使用は Xwayland）
- 指摘 3 の直しを float64 の 1 問ずつで行う場合：1 問は MOSEI の候補で音声 3.8 秒（319 回），融合 5.7 秒（283 回）．avt で 1 ファイル約 2.5〜3.5 分，av で約 1.5 分になり，96 ファイルで約 3 時間．指摘 5・7 の行を足すと 4〜5 時間，反復を 0〜4 にすると 7〜8 時間

## 指摘

### [D11，I1] 単位ごとの割合を，単位ファイルごとの比の平均で作っている
- 重さ：止める
