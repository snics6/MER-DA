### 当てはめが設計の目的関数の最適解か（確かめること (2)．`rc/check_softce.py`，出力 `rc/check_softce.out`）
合成 2 例（n = 800・d = 50，n = 300・d = 600）と実データ 2 例（MELD の候補の先頭 400 本の音声 1,024 次元，q = ref__0 と oracle）について，全行と無作為の半分の行で，λ 3 つの計 36 問を `fit_many` で解き，次を比べた．

- 1 問ずつ float64 の L-BFGS（勾配 1e−9 を目標）の解との損失の差は +1e−12〜+6.8e−9（束ねた解の方がわずかに大きい）．argmax の不一致は 36 問すべてで 0
- 確率の最大差は，学習に使った行の上では 1e−5 程度，使わなかった行の上では n < d かつ λ = 1e−3 のとき最大 1.0e−2（MELD の音声，200 行で 1,024 次元）．λ が小さく n < d のとき，損失がほぼ平らな向きに解が動き，学習に使わない発話の確率がずれる．試走の fit_check（全候補で解き，テストで測る）では確率の最大差 3.8e−4，テストの UAR の差は 8 問とも 0，損失の差 ≤ 5.1e−9

結論：q を 4n 行の重みで渡す形は，柔らかい交差エントロピーの最適解を与える．勾配 1e−6 での止め方による残りの差は，テストの argmax を動かさない大きさである．

## A．本番の規模の見積もり
- 単位ファイルの所要は単独の処理で前の測定と合う（MOSEI 443 秒．前回 434 秒）
